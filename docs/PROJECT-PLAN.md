## 1. 项目目标

### 1.1 一句话定义

一台能自主行动的移动式数字人终端：设备端负责"看见、生活、时间流逝"，PC 端负责"思考和说话"，两者在局域网内协同；**PC 不在时设备照样出画面、照样过日子**。

**显示上只有两态**（详解见 §10）：**总观**（默认、唯一常显：像素地图 + 她在哪 + 在干嘛）⇄ **显现**（把她叫到面前说话，Live2D + 语音）。**世界**不是显示态，是后台作业，运行时屏幕照旧是总观，只多一个词的状态标识。

**三条约束**（§10 引言）：
- **总观常显**——主机不在、断网、PC 从未装过，也要出画面、能拖能点（A14）。
- **显现需主机**——主机不可达就**不能进入**，不提供"降级显现"（A15）。
- **世界双档、主机优先**——**能连上主机核心就用核心机干活**（LLM + GPU 产资产，需求不变，§10.6）；只有主机不可达时才降为**端侧轻型档**，用设备现成硬件把日子接着过下去**并继续产出轻资产**（剧情 / 场景 / 背景，§10.7.3）。
  注意：**"主机可达"与"设备有网"是两件事**——设备端本身可以联网，端侧档不是"断网模式"。

### 1.2 产品形态（两条硬约束）

**约束一：PC 端是一个软件，不是一堆脚本。**

用户视角只有一个东西：安装包 → 双击 → 托盘图标 → 可用。不存在"打开终端跑第 3 个服务"这种操作。

| 零散部署的样子 | 本项目的样子 |
|---|---|
| git clone 5 个仓库 | 单个安装包 |
| 手动 uv sync / pip install | 内置运行时，首次启动自解压 |
| 手改 conf.yaml | GUI 配置，落库不外露文件 |
| 开 5 个终端分别启动 | Supervisor 托管，托盘一键启停 |
| 手动装 nginx 配证书 | 内置网关，自动签发并导出证书 |
| 端口冲突自己排查 | 端口自动分配 + 冲突检测 |
| 模型自己下载放目录 | 模型管理器按需下载、校验、切换 |
| 日志散落各处 | 单一日志出口，GUI 可查 |

**约束二：设备端零操作。**

上电 → **停在总观（默认态）**，这一步不依赖 PC 存在：kiosk 加载的是设备本地的只读壳（`127.0.0.1:8080`），不需要用户输 IP、不需要点连接、不需要配置。想看她正面说话就**一键（滑动开关 / 点击角色）**进显现，拨回来就回总观——**但主机必须可达**，否则开关只会回弹并给一句提示（§10.5）。**世界不用你管**——主机空闲时它自己在后台产资产（「世界·主机」），主机不在时降为端侧档接着过日子（「世界·本地」），屏幕上只有一个词的变化。

### 1.3 验收标准（可测，全部达成才算 M 系列完成）

| 编号 | 指标 | 目标值 | 测量方式 |
|---|---|---|---|
| A1 | 全新机器安装 | 单安装包，双击完成，零命令行 | 干净 Windows 虚拟机实测 |
| A2 | 冷启动到可对话 | < 60 秒 | 从双击图标到首次语音应答 |

| A5 | 长稳 | 连续 72 小时无崩溃 | 自动化脚本持续对话 |
| A6 | 服务异常自恢复 | < 10 秒 | kill 子进程后观察 |
| A7 | 断网恢复 | < 30 秒自动重连 | 拔网线再插回 |
| A8 | 主动打扰克制 | 每小时 ≤ 2 次，夜间静默，5 分钟响应率 ≥ 30% | `life.db: gate_log`（§9.11） |
| A9 | 跨会话记忆 | 能回忆 7 天前的事实 | 人工验证 10 条样本 |
| A10 | 显示态切换延迟 | 显现 ≤1.5s（热）/≤2.5s（冷）；回总观 ≤400ms；滑动开关响应 ≤200ms | 端侧打点 20 次取 P95（§10.12） |
| A11 | 世界产出与预算 | **主机档**：每夜 ≥1 个可用场景 + ≥2 张背景；日 output ≤8k tokens；抢占零失败。**端侧档**：24h tick 不断档、短句重复率 ≤20% | `world/outbox` + token 账本 + Worker 日志（§10.12） |

| A13 | 端侧自治与长时在线 | 主机消失后 60s 内自主接管不白屏；连续 8h（含 6h 息屏）不断档、无 OOM；事件 0 丢 0 重；息屏功耗降 ≥60% | 断电实验 + 事件计数 + 功率计（§10.12） |

| **A15** | **显现需主机（不可达必拒）** | 主机不可达时点击/拨开关 20 次：**0 次进入显现**、20/20 出提示气泡；主机恢复后首次进入 ≤2.5s | 自动化点击 + `state_log`（§10.12） |
| **A16** | **端侧轻资产产出** | 主机不可达 24h：产出 场景 ≥4、剧情 ≥6、背景 ≥3，全部可被显现/总观消费且带 `tier:edge` 标记；生成期 life tick P95 ≤8ms 不受影响；产物配额 ≤500MB；**程序化路径 0 token** | `world/outbox/edge/*` + manifest + 帧率打点 + 账本（§10.12） |

### 1.4 范围边界

**做：**
- Live2D 角色展示与语音对话
- 像素上帝视角生活场景（预设 + 模型生成变体）
- 主动唤醒（基于生活事件的自主发起）
- 声音克隆
- 长期记忆
- 桌面接管（远程遥控 PC，M9）
- 离线降级：总观常显 + 世界端侧续跑（**不提供离线对话/发声**，§10.1）

**不做（明确排除，防止发散）：**
- VRM / 3D 形象
- 直播平台对接、弹幕
- 多角色群聊
- 公网暴露（仅局域网）
- iOS / Android 原生客户端（用浏览器方案）
- 手机端 App
- 游戏联动（Minecraft / Factorio 等）

## 2. 架构

### 2.1 分层

```
┌───────────────────────────────┐        ┌────────────────────────────┐
│ PC 端（核心层 · 思考与发声/世界生产）  │ 设备端（表现层 + 端侧兜底） │
│ 数字人虚拟仓 桌面应用         │        │ Armbian + Chromium kiosk   │
│  ├ Supervisor（进程托管）     │        │ 本地壳 :8080（默认入口）   │
│  ├ OLVT 后端        :12393    │        │  └ 裁剪版 Web 前端         │
│  ├ TTS 服务         :9880     │  局域网 │      ├ 总观：地图/角色/状态 │
│  ├ WakeTrace        :8765     │◄──────►│      │   └ 脱离主机可显示   │
│  ├ 编排器 orchestrator :8877  │ 可缺席  │      ├ 显现：Live2D + 背景 │
│  │   ├ ModeController         │        │      └ 字幕/触摸/滑动开关  │
│  │   ├ LifeStream（§9）       │        │  life.worker（端侧档·零 token）│
│  │   ├ AssetForge（共享生成器）│        │  forge.worker（轻资产生成）│
│  │   └ AgentBridge / 世界生产 │        │   ├ LocalRuntime（降级数据源）│
│  ├ 记忆 Agent                 │        │   └ IndexedDB 事件/资产缓冲│
│  └ 网关（自动证书）  :8443    │        │  感知：WebAudio + VAD      │
└───────────────────────────────┘        └────────────────────────────┘
```

> **`AssetForge` 是两档共用的同一份代码**（§10.7.3）：主机档的 P0/P1/P2 生产本来就是"模型出**种子** → 本地**确定性生成**"，生成器从来就在本地。端侧档不新增生成器，只是**换一个种子来源**（状态机而不是模型）——这是"端侧也能产资产"成立的全部依据。

**四个维度**（§10.1）：显示态 `总观 ⇄ 显现` 决定设备内存与是否需要主机；**主机可达**决定显现能否进入、世界走哪一档；设备网络决定端侧档能否校时/更新资源（**与主机可达是两件事**）；世界档位 `空闲 / 主机档 / 端侧档` 决定 GPU 与 token 归谁。
**世界没有独立界面**，运行期屏幕仍是总观 + 一个词的档位标识。设备端两态互斥渲染，不共存。

**"总观可脱离 PC 显示"是架构级前提**：页面、地图、角色都不由主机提供（本地壳 `:8080`），否则主机一关就白屏，A14 无从说起。**但世界生产仍以主机为核心**——能连上就用核心机干活，连不上才降端侧轻型档。

**设备端自带降级运行时**（§10.7）：本地只读壳（`:8080`）+ `life.worker` + `forge.worker` + `LocalRuntime` + `IndexedDB` 事件缓冲。主机可达时它只是**备用数据源**；主机不可达时接管生活推进、记账，**并用 `forge.worker` 继续产轻资产**（剧情/场景/背景，A16）。

**关键判断：设备端不跑 Python，不跑 Electron，只有一个全屏浏览器。**

这是复用 Open-LLM-VTuber 前后端分离架构的直接结果。Live2D 渲染、VAD、音频播放全部在前端 Web 层，设备端零业务代码。

### 2.3 PC 软件内部结构

```
数字人虚拟仓.exe
├── 主进程（Tauri 2 / Rust）
│   ├── GUI：状态面板、模型管理、设备配对、日志
│   ├── 托盘：启停、状态灯、快速静音
│   ├── Supervisor：子进程生命周期、健康检查、崩溃重启
│   ├── 网关：HTTPS/WSS 反代、CA 签发、证书导出
│   └── 端口管理：自动分配、冲突检测
├── sidecar：olvt-backend（Python）
├── sidecar：tts-service（Python）
├── sidecar：waketrace（Python）
├── sidecar：orchestrator（Python）
│   ├── ModeController   显示态二态 + 世界档位三值（空闲/主机/端侧）+ 主机可达态、滞回、抢占、独立持久化
│   ├── LifeStream       生活流同步（§9）
│   ├── Gate / Echo      A8 闸门、回声
│   ├── IdleProbe        输入空闲 / 负载 / agent / 人工标记（主机档五项与门）
```

### 2.4 设备端结构（表现层 + 端侧兜底）

```
设备端（ARMbian）
├── Chromium kiosk → http://127.0.0.1:8080（默认入口，冷启动 ≤8s，不请求 PC）
├── 只读静态服务 :8080 → /opt/dhvw/www（frontend 44MB + Live2D 模型 + tileset + 短句池）
├── life.worker：tick 状态机 + LocalRuntime + IndexedDB 事件缓冲（主机不可达时接管）
├── forge.worker：AssetForge 端侧实例——地图生成 / 背景合成 / 剧情文法（§10.7.3）
├── systemd：关闭自动 suspend（否则端侧 tick 停摆）；守护本地壳进程
└── 数据：IndexedDB（world/）事件缓冲 ≤2000 条；资源包 ≤300MB；端侧产出 ≤500MB（LRU）
```

**设备端的可显示性不依赖主机**：页面、地图、角色、短句都在本地，主机不在也出画面（A14）。**她的"智力"在主机上**——要说人话必须走主机。**但"产出"不全在主机上**：地图、背景、剧情都有本地生成路径，主机不在时用低一档的方式继续产（A16）。

### 2.5 设备端降级策略

| 状态 | 行为 |
|---|---|
| 主机可达 | 总观与显现按**显示态**渲染（§10）；世界通常跑**主机档**，角标「世界·主机」 |
| 断连 < 60s | 保持画面，静默重连，世界无感知 |
| 断连 > 60s | 判**主机不可达**：角标转灰、Agent 卡变灰「主机未连接」、世界降到**端侧档**（角标「世界·本地」）、数据源切 LocalRuntime；若在显现则 10s 内退回总观并给气泡说明（A15） |
| 主机不可达时点角色 / 拨开关 | **拒绝进入显现**，只出一句气泡；不加载 Live2D、不出对话框 |
| 长时间不可达（数小时～数天） | 端侧档 + 息屏（1 tick/min）；**`forge.worker` 继续产轻资产**（场景/剧情/背景，日上限见 §10.7.3）；唤醒给"你不在的这段时间"摘要；事件缓冲满 2000 条环形覆盖并计数 |
| 主机恢复 | 先回流事件（≤3s）→ 再回流资产（`tier:edge` 入库，不覆盖主机产物）→ 切回主机档；显示态全程不变 |

**任何异常的落点都是总观**：它不依赖 GPU、不依赖 TTS、不依赖 LLM、也不依赖主机是否开着，只需要本地资源包。

### 2.6 总观 2D 场景与人物位置：不自研引擎，只自研粘合层

> 本节回答一个具体问题：**上帝视角 2D 地图 + 她在哪 + 她走动**，有没有现成项目可借鉴？结论是**有，而且很贴**，但**没有一个能整套直接装**——它们各自绑了自己的后端（Convex / 多人 WebSocket 服务器 / VS Code 宿主）。所以策略是：**格式与算法借成熟的，渲染与数据源自己粘**。

#### 2.6.1 四个候选（按贴合度排序）

| 项目 | 许可 | 它解决的问题 | 我们能拿的 | 不能拿的 |
|---|---|---|---|---|
| **pixel-agents**（`pixel-agents-hq/pixel-agents`，旧地址 `pablodelucca/pixel-agents`；扩展市场 ID 仍是后者） | MIT | 把"agent 正在干什么"画成像素小人在房间里走动、坐下、干活；自带布局编辑器、寻路、状态机、气泡 | **整套交互模型**——它做的正是"总观＝她在屋里＋PC 上 agent 在跑什么"这同一件事。渲染是 **Canvas 2D 而非 WebGL**；家具/地板的 `manifest.json` 机制、BFS 寻路、角色状态机（idle→walk→act）都可移植。**现已有 Standalone CLI**（`npx pixel-agents`），可脱离 VS Code 在浏览器里跑同一个办公室，是最快能看到成品观感的路径（§2.6.6） | 数据源是 Claude Code 的 JSONL；**只读观看模式下小人不会自己动**；美术资产许可需逐个核对（角色基于 JIK-A-4 Metro City） |
| **ai-town**（`a16z-infra/ai-town`） | MIT | LLM agent 在 2D 像素小镇里生活、移动、对话，前端 PixiJS | **位置与移动的建模**：`moveTo` 是 RTS 式"只给目标不给轨迹"；位置＝`position + orientation + speed`，用 `HistoricalObject` 历史缓冲存每 tick 快照，客户端**回放**得到平滑运动。**这条直接补上我们的漏洞**（见 2.6.4）。另有 Tiled→JSON 的管线思路 | 后端全绑 Convex（模拟引擎、数据库、向量检索都在里面），不可引入 |
| **WorkAdventure** | **AGPL-3.0 + Commons Clause** | 浏览器里走 2D 像素办公室，地图用 Tiled 做，靠近触发音视频 | **只看设计**：一张地图＝纯 JSON＋一个 script.js 的组织方式；区域（zone）触发的产品形态；**v0.22 后不再绝对禁用代码**——Commons Clause 限制的是「销售 / 以服务形式提供」，与本项目**非商用开源**定位不冲突（ADR-015） | 当前**无引入需求**；若真复制其代码，项目许可证需与 AGPL-3.0 兼容 |
| **LDtk**（`deepnight/ldtk`） | MIT | 不是运行时，是 **2D 地图编辑器 + JSON 格式** | **格式**：IntGrid 层天然当可行走/碰撞网格；auto-layer 规则自动拼 Wang tiles（省掉自研 autotile）；Entity 层放"她常待的点、家具、热点"；官方文档化的 schema 让**程序化生成合法 JSON 很容易** | 无（它只是编辑器，运行时不依赖它） |

**一句话**：**别自造场景格式**（用 LDtk 的），**别自造寻路**（用 BFS/easystarjs），**别自造渲染器**（用 Canvas 2D 直接合成分层图），**别自绘美术，也别拿通用瓦片硬拼地图**（直接用上游设计好的地图 + 成套素材，§2.6.7 / **§2.6.8**）。WorkAdventure 目前只看产品形态；其代码不再被许可口径一票否决（ADR-015）。

#### 2.6.2 选型结论：四层，各层的轮子从哪来

| 层 | 选什么 | 轮子来源 | 自研量 |
|---|---|---|---|
| 地图格式 + 编辑器 | **LDtk JSON**（`.ldtk` / `.json`） | LDtk（MIT） | 0（只写约 150 行解析 + 校验） |
| 场景生成 | `MapForge` 输出**同一份** LDtk JSON | 自研（复用 R23 质量闸门） | 中（M6-T7） |
| 运行时渲染 | **构建期烘焙分层 PNG → 运行时 Canvas 2D 合成** | 借鉴 pixel-agents 管线；`@pixi/tilemap` 降为备选 | 薄（约 300 行） |
| 人物位置 / 移动 | **网格 + BFS 寻路 + 位置外推** | `easystarjs`（MIT，7KB）或移植 pixel-agents 的 BFS；位置模型照抄 ai-town | 薄（约 200 行） |
| 角色动画 | sprite sheet（4 帧 × 4 向）+ 状态机 | 标准做法 | 薄 |

**为什么地图格式选 LDtk 而不是 Tiled**：两者都是 JSON + tileset PNG，生态上 Tiled 更大（ai-town、WorkAdventure 都用它）。但 LDtk 是 **MIT**（Tiled 编辑器是 GPL-2.0，格式本身自由，法务上要额外解释一轮），而且它的 **IntGrid 层（整数网格标 0/1/2 表示空气/地面/水）正好就是我们寻路要的 grid**，auto-layer 规则也省掉自研 autotile。`MapForge` 程序生成时，输出 IntGrid + tile 层即可，人工还能用编辑器直接微调同一份文件——**生成与手编共用一个格式，这是最重要的一点**。

#### 2.6.3 为什么运行时不用游戏引擎（修订 ADR-005 的理由）

ADR-005 当初定的是"自研渲染层 + `@pixi/tilemap`"。查证后有三条理由需要修：

1. **总观的画面是静态的**：一张地图 + 一个小人。构建期把地形/家具/光罩各烘一张 PNG，运行时每帧只 `drawImage` 2–4 次再画角色。**这个场景不需要 tilemap 引擎**。
2. **`@pixi/tilemap` 维护缓慢**：v4.1.0（2024-01）→ v5.0.2（2025-07），单人维护，其自述的 Canvas fallback 比原生慢 5 倍。作为**核心**渲染件依赖它，风险大于收益（当然仍可用，故列为备选并锁版本）。
3. **总观态根本不需要 WebGL**：只有 Live2D 需要。两态互斥渲染（§10.2）下，总观走 Canvas 2D 意味着 **WebGL 上下文、纹理、shader 都不在内存里**——对 2GB 和 A14 的"冷启动 ≤8s"是净收益。

**代价（写清，不藏）**：动态 tile 变化（她挪了家具、天气换图层）不能"改一块 tile"，必须**重新合成那一层**（960×540 分层重绘 ≤120ms）。可接受，因为这类变化是"一天几次"而不是每帧。**回退路径**：分层容器的抽象不变，把渲染后端换回 `@pixi/tilemap` 即可；M6-T10 做对比 spike 后再定稿。

#### 2.6.4 必须修正的一处现有设计：位置不能靠 5s 快照

§10.4 原来写"在线时 `state:overview` 5s 推送一次"。**这对状态成立，对位置不成立**——5s 一个坐标，小人在屏幕上会瞬移。

改成（照 ai-town 的做法）：

- **下行**：`moveTo { targetGrid, path[], speed, t0 }` **事件式**，只在她改变意图时发（几十字节，比每 5s 推全量位置更省）
- **前端**：持有 `PathAgent`，按 `t0` + `speed` 本地推进格子插值；`state:overview` 只带 `pos_checksum` 做纠偏（偏差 >1 格才强制吸附）
- **断连**：`LocalRuntime` 接手**同一个 `PathAgent`**，只是意图来源换成端侧状态机 → **数据源切换不重置位置**。这就是"视图只订阅抽象 `LifeStore`"这句抽象话落在代码里的具体形状
- **tick**：不需要 ai-town 的 60Hz。总观静止 8fps、行走 30fps，0.35s/格插值足够

#### 2.6.7 观感边界：三版对照，原型粗糙是刻意简化，不是开源上限（v0.23 修正结论）

> **触发**：v0.19 需求方问「地图、物品、人物是不是太粗糙，是你做得粗糙，还是此开源就这么粗糙」；v0.21 追问「上面和下面是不是都是你画的」；v0.22 要求「上带素材的版本，三个版本比较」；**v0.23 需求方指出「效果还没有程序化美术好」**。
> **结论（v0.23 修正）**：**A / B 都是我写的 JS，0 张图片；C 是上游 ai-town 官方地图。** 粗糙来自原型简化，与上游开源项目无关。但 v0.22 的第一版 C 用通用瓦片硬套，观感确实**输给了 B**，不能写成「换素材就自动更好」——逐条复盘见 **§2.6.8**。真正成立的是：**采用上游已经设计好的地图 + 成套多帧角色，才能既省自绘代码又拿到观感**。

**为什么原型是粗糙的**：`prototypes/overview-demo.html` 的硬目标是「单文件 / 零依赖 / 离线可跑 / **不碰任何第三方美术素材**」，所以地图、家具、人物全部用纯色 `fillRect` 绘制——人物只有 6 个矩形。它验证的是机制（分层合成、`moveTo` 插值、断连接管、A15 离线拒绝），**不是观感**。v0.22 的 C 块试图补上这一课，但第一版失败；v0.23 重做（§2.6.8）。

**粗糙感的三个真实来源（都与上游无关）**

| 因素 | A 矩形基线 | B 程序化像素 | C 上游官方地图 |
|---|---|---|---|
| 像素密度 | 直接在显示分辨率画 32px 大色块 | 416×240 低分辨率逐像素作画 → 2× 最近邻放大；描边、抖动、颗粒感成立 | 上游地图原生 16px/格，烘焙成 416×240 后同样 2× 放大；每格都是画好的地形瓦片 |
| 光影与纹理 | 每件家具 3–5 个纯色矩形，无投影 / 高光 / 材质 | 用 2242 个矩形硬堆木纹 / 砖缝 / 反光，仍是几何拼贴 | 草地纹理、树干投影、水面波纹、栅栏描边、沙路颗粒全在上游图集里，**无需自绘** |
| 角色动画 | 身体 1 块、头 1 块、腿 2 块，正弦摆动；无朝向、无帧 | 2 帧行走 + 头发高光 + 朝向眼位，仍是 29 个矩形 | **4 方向 × 3 帧** 32×32 精灵（96 帧图集），朝向与步态都是上游现成的 |

**五档观感，别把原型当成产品上限**

| 档 | 谁画的 | 说明 |
|---|---|---|
| ① v0.19 原型 | 我，纯色矩形 | 色块级；零第三方素材；只验机制 |
| ② 对照页 B 块 | 我，程序化逐像素（约 200 行） | 开始像像素游戏，但仍是**为这张地图量身写的自绘近似**，换一张图就要重写；零外部素材；**不进产物包** |
| ③ **v0.22 被否决的 C** | Kenney Tiny Dungeon + Tiny Town（CC0）+ 约 60 行运行时瓦片映射 | **反面教材：比 ② 还难看**（§2.6.8）；文件留证，页面与产物包不再引用 |
| ④ **对照页 C 块（v0.23 重做）** | **ai-town 官方地图**（`tilemap.json` 三层烘焙）+ 官方 96 帧精灵（MIT / 上游美术致谢） | 上游已把地图设计好，我们只做烘焙与角色切片，**场景 0 行自绘代码** |
| ⑤ 正式版总观 | **不自绘**——成套素材 + LDtk 手工设计 + Super Simple Export 烘焙 | 关键不是「用了素材」，而是**素材与地图设计配套**；M6-T11 做 LDtk 模板与碰撞层统一导出 |

**三版定量对比（同一 26×15 网格 / 同一 `PathAgent`，v0.23 运行时实测）**

| 指标 | A 矩形基线 | B 程序化像素 | C 上游官方地图 |
|---|---|---|---|
| 场景怎么来的 | `fillRect` 大色块 | `fillRect` 低分辨率细节 | 上游 `tilemap.json` 三层烘焙成 1 张 PNG，直接 `drawImage` |
| 烘焙图元 | 377 个矩形 | 2242 个矩形（≈6×） | **1 次 `drawImage`**（416×240 裁片） |
| 用过的颜色数 | 23 | 93 | **48**（上游地图裁片，自带统一调色板） |
| 每帧动态 | 6 个矩形 | 29 个矩形（≈5×） | **1 次 `drawImage`（角色切片）** + 阴影 / 光罩 |
| 外部素材 | **0 张** | **0 张** | **2 张 PNG**（地图裁片 9.8 KB + 96 帧精灵 175 KB）；上游图集 192 KB / 地图 JSON 117 KB 离线留档 |
| 场景绘制代码 | 约 40 行 | 约 200 行 | **0 行**（地图来自上游；仅角色切片 + 光影约 15 行） |
| 许可 | 无第三方素材 | 无第三方素材 | ai-town 仓库 MIT + 上游美术致谢，已登记 `docs/ASSETS-LICENSE.md` |

> **v0.23 更正（原结论撤销）**：v0.22 曾写「C 颜色最少、文件最小却赢了」——**该结论已被需求方实测否决并作废**。第一版 C 颜色少、体积小，画面却明显更差；**颜色数、文件体积、`drawImage` 次数都不是观感指标**，不得再拿它们论证「更好看」。当前 C 的优势在于**地图由上游设计好、无需自绘**，而不是色数。
> **A / B 仍不是正式版候选**：无 tileset 复用、无成套多帧精灵；仅用于观感对齐，不进产物包。
> **C 也不是可集成模块**：无 LDtk 解析 / 资源包打包流程 / Worker / 真实主机通信；且**碰撞层与 A/B 家具未对齐**（上游地图自带树 / 栅栏 / 水域），正式版由 LDtk 统一导出（M6-T11）。

**许可口径**：需求方已明确**项目不涉及商用、目标是开源发布，不用在意被追责**（§1.5 / ADR-015）。C 块因此可直接使用 ai-town 的 MIT 仓库素材，只需保留许可原文与上游美术致谢；R28 降为低影响。但 **v0.23 补充**：许可宽松**不构成观感背书**，选型第一判据仍是「是否成套、是否与地图设计配套」（§2.6.8 / R31）。

> **一个容易误会的点：这不是 Canvas 2D 的锅。** 美术精细度取决于**素材分辨率与帧数**，与 Canvas 2D / WebGL 无关。低分辨率离屏画布 + `drawImage` 最近邻放大正是像素游戏的标准做法，在 RK3566 / 2GB / 1080p 上比再开一个 WebGL 上下文更省——这也是 §2.6.3 选 Canvas 2D 烘焙的理由。**M6-T10 spike 只比渲染性能与冷启动，不比美术。**

**三版的定位**：`prototypes/overview-art-compare.html`（`preview-art-compare.bat`）是**观感对齐物**，不是可集成模块；其中 A/B 的程序化绘制**不得进入产物包**（否则就是自绘美术、重复造轮子）。C 块依赖 `prototypes/assets/` 两张本地 PNG，已用无头浏览器验证 `file://` 直接打开即可离线渲染；底图由 `scripts/bake_aitown_map.py` 从上游原始图集与地图 JSON 离线烘焙、可复现。机制验证基线仍是 `overview-demo.html`。

#### 2.6.8 素材版翻车复盘：素材 ≠ 观感（v0.23 新增）

> **触发**：v0.23 需求方看了 v0.22 的三版对照后指出「你自己看过吗？效果还没有程序化美术好」。复核无头浏览器截图后确认**属实**：第一版 C 的地板是橙色条纹壁纸、家具是同一瓦片平铺出的格子墙、地毯是红白棋盘、角色只剩 16×16 单帧小脑袋，整体明显差于 B。
> **性质**：不是 Kenney 素材包粗糙，也不是 CC0 许可问题，而是**我们的用法错了**。

**五个根因与修正**

| 根因 | 症状 | 修正 |
|---|---|---|
| 素材风格不匹配 | Tiny Dungeon 是地牢石墙、Tiny Town 是室外草 / 红屋顶，拿来拼温馨书房必然串味 | 换成自带成套地图设计的 `ai-town` 官方地图与图集 |
| 把瓦片当贴图平铺 | 16×16 家具瓦片铺满 2×6 矩形 → 格子墙；木纹瓦片铺满地面 → 条纹壁纸 | 瓦片按物件轮廓逐格摆；本页直接用上游烘焙好的地图，运行时不再拼场景 |
| 没有地图设计 | 60 行通用映射 vs B 版 200 行量身绘制，本来就不是公平比较 | 正式版用 LDtk 手工设计，地图与素材同批选定（M6-T11） |
| 色阶 / 光照不统一 | 亮橙木纹 + 灰蓝石墙 + 红屋顶 + 荧光绿树，四套调色板挤一张图 | 用上游地图自带统一调色板（裁片 48 色），只叠一层运行时光罩 |
| 角色单帧且偏小 | 16×16 单帧立绘 + 水平翻转，看起来只有一个小脑袋 | 换 32×32 的 4 方向 × 3 帧精灵，按 `dirX/dirY` 与行走帧切片 |

**期间试拼过的错误路线（留证，勿重复）**：v2–v6 共五版，先后试过「纯棕地板 + 单格物件」「成套红木家具块 + 石墙」「官方沙路瓦片铺地」「按 B 版构图逐件替换」，均因**这套 16×16 图集是室外 / 建筑包、根本没有室内木地板瓦片**而失败；反复把墙砖 / 屋顶瓦当木地板铺，越修越糟。结论是**不能靠小修小补救一套风格不匹配的素材**。

**定稿结论（写入 R29 / R31）**

1. **素材 ≠ 观感**：同一套素材，映射方式与地图设计决定上限；把通用瓦片硬套进一张为别的目的量身绘制的地图，一定输给量身绘制本身。
2. **不重复造轮子的正确落点**：直接用上游**已经设计好的地图**（`ai-town` 的 `tilemap.json`）与成套素材，而不是自己写运行时瓦片拼装。本页 C 因此做到**场景 0 行自绘代码**。
3. **定量指标要选对**：颜色数、文件体积、`drawImage` 次数都**不是**观感指标。观感评审只能以真机渲染 + 人工看图为准。
4. **v0.22 的错误结论已撤销**：§2.6.7 中「C 颜色最少、体积最小却最好看」及 ADR-015 里「直接解锁 Kenney C 块」的表述同时作废；Kenney 两套图集保留在 `prototypes/assets/` 作反面教材留证，页面与产物包不再引用。

**落地（离线可复现）**：`scripts/bake_aitown_map.py` 读取 `aitown_tilemap.json`（terrain / bridge / deco 三层，含 Tiled H/V 翻转标志）与 `aitown_rpg-tileset.png`，烘焙 26×15 裁片 `aitown_map_crop.png`；角色取 `aitown_32x32folk.png` 的 4 方向 × 3 帧。许可与致谢见 `docs/ASSETS-LICENSE.md`。

**待办**：C 的碰撞层仍与 A/B 家具不一致（角色起始格恰落在上游地图的一棵树冠上，即未对齐的直观示例）；正式版由 LDtk 统一导出碰撞层（M6-T11）。

### 2.7 模块缺口盘点与记忆/向量检索定稿（v0.24）

> 本节回答两个问题：① 盘点 §2.2 全表后，**哪些模块其实还没有找到可用上游案例**；② 其中被点名的**记忆 / 向量检索**，给出一个经核实、能直接进安装包的合格案例，把 ADR-004 与 M8-T1 挂了很久的"待定"关掉。

#### 2.7.1 三类模块：已落实 / 合理自研 / 真缺口

#### 2.7.3 四个候选逐一核实（2026-11-10 实查）

元数据取自 GitHub API 与官方文档；`pushed_at` 为仓库最后提交日，**不是**发版日。

| 候选 | 许可 / 星标 / 最后提交 | 逐条判定 | 结论 |
|---|---|---|---|
| `mem0ai/mem0` | **Apache-2.0** / 68,735 / 2026-11-06 | 官方文档确认默认 LLM = OpenAI `gpt-5-mini`、embedder = `text-embedding-3-small`、vector store = Qdrant；`Memory.add()` **每次都调 LLM 做事实抽取**（第三方评测亦指出 "every add calls an LLM"）；只有向量检索，**无 FTS5 全文、无时间衰减内建**；记忆落在向量库里，迁移要写导出脚本 → C1 △ / C2 ✗ / C3 △ / C4 ✗ / C5 ✗ / C6 ✓ | **不作落地基线**。只借它的**抽取 → 更新 → 去重**流程（M8-T4），不整套引入 |
| `getzep/graphiti` | **Apache-2.0** / 32,705 / 2026-11-09 | 时序事实有效期窗口 + 语义/BM25/图遍历混合检索，**概念上最贴 M8-T5**；但要求自带 Neo4j / FalkorDB / Kuzu 图库，每个 episode 都要 LLM 抽实体 → C1 ✗ / C2 ✗ / C4 ✓ / C6 ✓ | **不引入**。只借鉴「事实带有效期、被新事实取代而非删除」的建模（对应 §2.7.4 的 `supersedes`） |
| `tigerless-labs/agent-memory` | **MIT** / ~964 / 2026-09 创建 | 架构几乎完美命中：Markdown 是唯一事实源、SQLite FTS5 索引可删可重建、**库内没有 LLM 客户端、读路径不调模型不联网**、自带取代与时间范围、L0 分层返回。但**仅 2 个月历史、0.1.0、无 PyPI release**，且面向 coding-agent CLI → C1 ✓ / C2 ✓ / C5 ✓ / **C6 ✗** | **架构借鉴，不作基线**（成熟度不够，不能压在 A9 上） |

#### 2.7.4 M8-T1 定稿方案

**直接引入的只有两个 pip 包**（都装在 PC 的 `orchestrator` sidecar，设备端 0 新增依赖）：

| 层 | 选型 | 许可 / 体积 | 作用 |
|---|---|---|---|
| 向量索引 | `asg017/sqlite-vec` 0.1.9 | Apache-2.0 / MIT；纯 C 扩展 | `vec0` 表做 KNN；0.1.x 是暴力扫描无 HNSW，记忆库几千条量级完全够（R32） |
| 全文索引 | **SQLite 内建 FTS5** | SQLite 公有领域 | `tokenize='trigram'` 做中文子串匹配，与向量同库同事务 |
| 本地 embedding | `qdrant/fastembed` 0.9.1 + `BAAI/bge-small-zh-v1.5` | fastembed **Apache-2.0**；模型 **MIT**、512 维、约 90 MB | ONNX Runtime CPU 推理，**不引入 torch**；中文专项，512 维短文本够用 |
| 融合 | 自研约 30 行 Python | — | `0.5 × KNN + 0.3 × BM25 + 0.2 × 0.5^(age/30d)`；`tier`（L0–L3）参与加权，L0 常驻注入不参与衰减 |
| 写入策略 | 借 `mem0` 流程，**不整套引入** | — | 会话结束**批量**抽取 + 规则预筛；LLM 调用计入日 8k 硬顶；主机离线时只追加原始事件，**不写 L0–L3**（§10.7.5 口径不变） |
| 事实演进 | 借 `graphiti` 建模 | — | `mem_meta` 带 `ts` / `source` / `supersedes`，改口只标取代不删旧，满足 A9「回忆 7 天前」且能答"以前喜欢什么" |
| 设备端 | 只下发摘要 JSON | — | 端侧只有浏览器、2GB 内存，**不加载 `.db`、不跑 embedding**；M8-T6 口径不变 |
| 审计 | 借 `agent-memory` 理念 | — | 索引可重建：删掉 `vec0`/FTS5 由 `mem_meta` 正文重灌；正文可导出人类可读快照 |

**落库结构**：`%APPDATA%/DigitalHuman/data/memory.db` 单文件 → `mem_meta(id, body, tier, ts, source, supersedes)` + `mem_vec(vec0)` + `mem_fts(FTS5 trigram)`；备份就是复制一个文件（C5）。

**与 §2.2 / ADR-004 的关系**：ADR-004「走 Agent 接口自建、不依赖 Letta」**不变**；本次只是把它的"备选：mem0 或自建 sqlite-vec"二选一**收口为自建 sqlite-vec**，并明确 mem0 只作策略参考。新增 **ADR-017** 记录本次决策。

| M8 任务 | 定稿后的做法 |
|---|---|
| M8-T1 | **已定稿**（本节 + ADR-017） |
| M8-T2 | 四层 schema 落 `memory.db`：`mem_meta` / `vec0` / `fts5` 三表，L0 常驻块单独缓存 |
| M8-T3 | 仍走 OLVT Agent 接口，不碰后端核心（R1） |
| M8-T4 | 借 mem0 的抽取/更新/去重，改**会话末批量**；不每轮调 LLM（C2） |
| M8-T5 | 三路融合公式如上；spike 见 **§8.17** |
| M8-T6 | 设备端只收摘要 JSON，不加载向量库 |

**分发代价（如实记）**：PC 侧新增 `onnxruntime`（14.9 MB wheel）+ `numpy` / `tokenizers` / `huggingface-hub` 等约 60–100 MB 运行时依赖，加约 90 MB 模型；**模型必须随安装包预置或由 M2 模型管理器离线导入**——本机实测直连 HuggingFace 超时（E20），不能假设用户运行时能拉到模型。设备端 0 新增。此项并入 R4（打包体积）一起验。

#### 2.7.5 实测结论（详见 §8.17）

`scripts/spike_memory_vector.py` 在 Windows / Python 3.13.14 / SQLite 3.53.1 上跑通：10 条中文记忆，`vec0` KNN 10 命中 **0.64 ms**、FTS5 2 命中 **0.08 ms**，三路融合把「京都看枫叶 + 米色风衣（7 天前）」排第 1、把同字面但 30 天前的旧记忆排第 2，**时间衰减生效**。`trigram` 的两个中文坑已记入 **E19**。**真实中文 embedding 两轮下载（直连 / 镜像）均超时，「语义召回质量」尚未实测**——如实记入 §8.17、R33、E20，不以"应该能跑"冒充实测；M8-T5 接入前必须补跑 `--real-embed` 并用 A9 的 10 条样本人工验收。

## 6. 架构决策记录（ADR）

### ADR-001 采用 Open-LLM-VTuber 作为主框架

- **日期**：2026-11-09
- **状态**：已接受
- **背景**：需要 Live2D + 语音对话 + 打断 + 多 ASR/TTS 模块，自研成本极高。
- **决策**：以 OLVT 为底座，复用其前后端分离架构。
- **理由**：MIT 许可；前后端天然分离，与"核心-表现层"划分吻合；已实现 VAD、语音打断、Live2D 表情、MCP 客户端；ASR/TTS 模块化覆盖所需方案。
- **后果**：受上游 v2.0 重写影响，需锁版本并隔离改动。

### ADR-002 设备端用浏览器 kiosk，不做原生客户端

- **日期**：2026-11-09
- **状态**：已接受
- **决策**：设备端仅运行 Chromium kiosk 加载 PC 页面，不打包 Electron / Tauri 应用。
- **理由**：OLVT 前端即 Web 应用；省去跨平台打包与 Rust 交叉编译；业务代码零重复。
- **后果**：必须解决 HTTPS 证书信任；内存受 Chromium 制约。

### ADR-003 PC 端打包为单一桌面软件（Tauri + sidecar）

- **日期**：2026-11-09
- **状态**：已接受
- **决策**：用 Tauri 2 做外壳，Python 服务作为 sidecar 由 Supervisor 托管。
- **理由**：Tauri 的 sidecar 机制专为托管外部二进制设计；体积小；Rust 管进程生命周期可靠；Windows 自带 WebView2。
- **备选**：Electron + Node child_process（若团队更熟 TS 生态）。
- **后果**：需要 Rust 工具链；打包流程复杂化。

### ADR-004 记忆系统走 Agent 接口自建，不依赖 Letta

- **日期**：2026-11-09
- **状态**：已接受
- **背景**：OLVT 文档称 v1.2.0 引入 Letta 长期记忆，README 又称"暂时移除"。
- **决策**：不依赖内置记忆，通过 Agent 接口自建。
- **备选**：mem0（成熟、有托管能力）或自建 sqlite-vec（轻、可与本地 SQLite 同栈）。
- **~~待定~~ v0.24 已收口**：二选一结束，见 **ADR-017 / §2.7**。落地基线选 **自建 `sqlite-vec` + 内建 FTS5 + 本地中文 embedding**；`mem0` 只借「抽取 → 更新 → 去重」流程（其 `add()` 每次调云端 LLM、默认 Qdrant，违反 C1/C2），`graphiti` 只借事实有效期建模（需图数据库）。**本 ADR 主体结论「走 Agent 接口自建、不依赖 Letta」不变**。

### ADR-005 像素场景自研渲染层，用 @pixi/tilemap

- **日期**：2026-11-09
- **状态**：已接受；**渲染后端部分被 ADR-014 修订**（"自研薄层"结论保留，"用 @pixi/tilemap 且共用 WebGL context"改为"优先 Canvas 2D 烘焙，`@pixi/tilemap` 为备选"）
- **决策**：在 OLVT 前端新增场景层，与 Live2D 共用 PixiJS 渲染器。
- **理由**：无现成开源项目覆盖"Live2D + 像素场景"组合；@pixi/tilemap 与现有技术栈同源，共用 WebGL context 不增加内存。
- **后果**：这是全项目唯一需要自研的渲染模块。
- **v0.18 复盘**："共用 context 不增加内存"这条推理在**两态互斥**（§10.2）下不成立——两态不同时驻留，共用就没有收益；反而让总观态白背一个 WebGL 上下文。详见 ADR-014 与 §2.6.3。

### ADR-006 2GB 内存定型，按极限优化推进

- **日期**：2026-11-09

### ADR-009 主动性走「生活流 + 注入」，不走 MCP 工具调用

- **日期**：2026-11-10
- **状态**：已接受（实测驱动）
- **背景**：M7 原计划用 MCP 让虚拟人调用 WakeTrace 工具。实测三条硬伤（§8.14）：MCP `call_tool` 必失败（两版客户端均复现）、无 webhook 导致 `message` 降级、判定极保守 3/3 沉默。另有"两套脑子"与时区 bug。
- **决策**：
  1. WakeTrace 降级为**内容提供方**，只经 REST 拉 `/world/timeline`；
  2. 生活事件经**注入块**进入 OLVT，位置固定在历史之后、本轮输入之前（保护前缀缓存）；
  3. 主动开口由我们的 A8Gate 决定，通过**进程内 `POST /dhvw/proactive`** 复用设备连接投递（§9.5）；
  4. 不引入 MCP，不新增工具 schema（省 301 tokens/轮，也绕开官方 `tools`+`reasoning_content` 的 400 约束）。
- **后果**：
  - 少一跳、低延迟，权限归位到本项目；WakeTrace 挂掉不影响对话（fail-open）。
  - 需要自建 5 个小组件（LifeStream / ContextComposer / A8Gate / ProactiveSpeaker / Echo），约 1.5 周。
  - 新增补丁 3（主动发言支持上下文载荷）与补丁 5（进程内端点），fork 改动继续累积，需维护补丁清单。
  - 主动发言的历史连续性不由 OLVT 负责（`skip_history`），统一由 Echo 在注入层补，避免孤儿 assistant 消息。

### ADR-010 显示只有两态，世界是后端工作态（v0.13 修正）

- **日期**：2026-11-10（v0.12 初版，v0.13 按需求方澄清修正）
- **状态**：已接受（v0.16 复核确认：世界仍是后端生产态，未见变更）
- **背景**：原设计把设备屏幕等同于 VTuber 界面，导致三件事互相打架：① 2GB 设备长期跑 Live2D 不现实；② 用户不对话时屏幕无事可做；③ 场景与背景图需要生成，而生成又要抢 GSV 占用的显存。
  v0.12 初版把解法写成"三态显示"（总观/显现/世界），但需求方指出：**世界是后端工作模式，前端只需保持总观并标记"世界工作中"**。三态显示会让前端白背一套用不到的视图。
- **决策**：
  1. 拆成**两个正交维度**：**显示态**（总观 / 显现，用户可见）× **工作态**（空闲 / 世界，仅一个角标）；
  2. **总观为默认**，开机即此；**显现**是"消费态"，要求 TTS 在线，背景与场景必须**事先备好**，进入只做展示；
  3. **世界是后端生产态，没有独立前端视图**：不占屏幕、不要求 TTS，把 4–5GB 显存让给场景/图像生产；只在主机空闲时运行、必须可抢占、单周期上限 30min；
  4. **非法组合只有一种**：`显现 + 世界`（抢同一块 GPU）→ 进显现前必须中止世界；
  5. 显示态互斥渲染，切态即释放（设备内存 / 显存 / 进程）；
  6. 新增 `orchestrator` sidecar 承载 ModeController、IdleProbe、WorldProducer、AgentBridge（本期 Stub）；
  7. 交互以**滑动二切开关**（总观 ⇄ 显现）为一等入口，硬件未定型前先用屏幕内虚拟开关，事件源抽象为 `DisplaySwitchSource`。
- **后果**：
  - 2GB 设备只需保证"一个显示态达标"，且世界期间**渲染路径与总观完全一致**，A4 从"整体压内存"变成"分态压内存 + 世界零增量"，风险显著下降（R11 仍需实测）。
  - 生成能力获得专用时间窗与显存，**token 消耗与 GPU 占用都从"随时可能发生"变成"空闲时批处理"**。
  - 世界引入自主操作主机的风险面（R12），必须白名单 + 可回滚 + 无网络发布。
  - **代价**：世界运行期间前端无感知（只有角标），排障依赖 `state_log`；已列为 §10.14 风险并给出对策。
  - M9「工作模式」更名为「桌面接管」，优先级高于两个维度（§10.10）。
  - 新增里程碑 M11（4 周），成为项目最长链（需 M5/M6/M7 同时就位）。

### ADR-011 端侧自治：设备自带世界运行时，PC 不是宿主

- **日期**：2026-11-10
- **状态**：已接受（需求方提出"生命仓长时间在线"；v0.16 复核确认双档与主机优先不变）
- **背景**：原设计把世界当成 PC 端后台作业，隐含假设是"PC 一直开着、连着"。但设备是长时间在线的生命仓：晚上关电脑、出差、断网都是常态。在这个前提下，**PC 一关她就不存在了**，产品设定直接崩塌。
  更糟的是当时连"页面"本身都由 PC 的 `:12393` 提供——PC 一关是白屏，连"离线待机画面"都做不到。
- **决策**：
  1. 世界拆**两档**：主机档（LLM+GPU 产资产）/ 端侧档（本地状态推进，零 token 零 GPU）；
  2. PC 心跳丢失 >60s → **端侧档自动接管**；PC 恢复 → 先同步事件再切回主机档，显示态全程不变；
  3. **设备本地起只读静态壳**（`127.0.0.1:8080`），kiosk 默认指向它。PC 只是数据源，不是宿主；
  4. 端侧运行时 = **Web Worker + IndexedDB**，不引入任何 Python/Node 常驻进程（保持"设备只有一个浏览器"）；
  5. 端侧**只追加事件，不写记忆库**；合并靠 `clock_offset` 校正 + uuid 去重；（**v0.17 修订**：端侧可产 `tier:edge` 轻资产，见 ADR-013）
  6. 长时在线配套：10 分钟无互动息屏、引擎改 `setInterval` tick（不依赖 rAF）、关掉系统 suspend。
- **后果**：
  - 页面离线可启动 → 顺带解决"设备端要装根证书才能用麦克风"的麻烦（`127.0.0.1` 本身是 secure context）；WSS 保留但不再是必需（§8.13 前提被替代）。
  - 代价 1：局域网内走明文 `ws://`，需要在 GUI 中说明；要加密仍可启用网关。
  - 代价 2：端侧档带来 ~60MB 额外内存（**v0.17 修订为 ≤100MB**，含生成 Worker），2GB 上必须实测；超限则按序砍生成能力（§10.14）。
  - 代价 3：两套运行时 → 两套潜在 bug；用统一 `LifeStore` 接口隔离，视图不感知数据源。
  - 端侧档不能发声（无 GSV）→ 原结论为"离线显现降级为静态立绘 + 预设台词"，**已被 v0.16 推翻**：主机不可达时一律**拒绝进入**显现（A15），不提供降级形态。
  - 新增 A13 与 M11-T11~T14，M11 工期 3 周 → 4 周；新增 R18–R20。

> **v0.16 更新**：本 ADR 的"双档"与主机优先原则**保持不变**；仅"离线显现降级为静态立绘 + 预设台词"一条被 **ADR-012** 推翻（主机不可达时一律拒绝进入显现）。

### ADR-012 总观常显 / 显现绑定主机 / 世界双档保持主机优先（v0.16 定稿）

- **日期**：2026-11-10（v0.15 初稿，v0.16 按需求方澄清纠正）
- **状态**：已接受
- **背景**：需求方提出三条：① **主机端离线，显现模式无法使用**；② **总观是默认模式，必须能常态展示**；③ **世界模式在连不上主机时转为端侧轻型运作**。
  v0.15 把 ③ 误读成"取消主机档、离线优先"，并把资产生产降级为默认关闭的可选扩展。需求方纠正：**主机世界的要求不变**，③ 只是在举例说明"无法连接主机"时的降级行为；**端侧档也不是断网模式**，设备本身可以联网，轻型只表示"用现成硬件资源干活"。
- **决策**（三条约束，双档不变）：
  1. **总观常显**：默认态，任何情况下都要出画面。离线壳 + 本地资源包 + `LocalRuntime` 因此从"端侧档的前提"升为**总观的前提**；M11-T12 最先落，A14 专测。
  2. **显现绑主机**：主机不可达一律**拒绝进入**，删除"离线降级显现"（静态立绘 + 预设台词作废）；显现第一道闸门从 TTS 改为**主机可达**，A15 专测。
  3. **世界保持双档、主机优先**：主机可达且五项与门通过 → **主机档**（LLM + GPU 产资产，§10.6 需求一字未改）；主机不可达 → **端侧档**（CPU + 本地 `AssetForge` 续经历**并产轻资产**，程序化路径零 token 零 GPU，§10.7 / §10.7.3）。
  4. **"主机可达"与"设备有网"必须分开建模**：端侧档不要求网络，也不排斥网络（网络用于校时 / 资源更新 / 可选增强）。
  5. 进显现：主机档**中止**（让出 GPU，checkpoint 续跑）、端侧档**暂停**（停 tick 保留状态）。
  6. 桌面接管：主机档必须中止（远程桌面要 GPU），端侧档可继续（零 GPU 不抢资源）。
  7. 背景图网络源保留但默认关（R13 不变）。
- **后果**：
  - 世界生产的路由清晰：**有主机用主机，没主机用自己**；两档共用 `AssetForge`，风格分裂风险靠"同一份生成器"而不是"端侧不产"来消除（R20，v0.17 修订）。
  - token 预算与验收回到 v0.14 口径（A11 产出与预算、A12 显存释放），另新增 A14（总观常显）、A15（显现需主机）。
  - M11 主线：T12 离线壳 → T2 总观（含不可达形态）→ T16 常显实测 → T11 端侧引擎 → T1 档位状态机 → T15 不可达拦截 → T10 开关 → T3 显现 → T4/T5/T6 主机档 → T7 → T13 → T8/T14。
  - 新增 R21（主机不可达被误判为故障）、R22（端侧档表现力天花板）。
  - **代价**：主机不在时她**不能说话**——这是明确接受的产品取舍，不用降级形态掩盖。（**v0.17 修订**："也不产新资产"这条撤回，端侧改为产 `tier:edge` 轻资产，见 ADR-013）

### ADR-013 端侧也能产资产：共用 AssetForge + 质量分层（v0.17）

- **日期**：2026-11-10
- **状态**：已接受（需求方提出"长时间不可达，端侧也可以产资源"）
- **背景**：v0.14–v0.16 反复把"端侧不产资产"当成硬约束，用"避免两套生成器风格分裂"作为理由。需求方指出这条路走不通：**主机不可达可能持续数天**，如果端侧只能写事件、不能产出任何东西，那么她"离线这几天"在屏幕上是没有新内容的——生命仓长时间在线的设定就只剩"能动"，没有"在过自己的日子"。
- **关键发现（这条决定了整个方案的成本）**：主机档的 P0/P1/P2 生产**本来就是"模型出种子 → 本地确定性生成"**（§10.6 任务表、§10.9 token 降耗设计）。也就是说 **生成器从来就在本地**，模型只负责出一个语义种子或一段 prompt。
  → 因此端侧不需要"新增一套生成器"，只需**换掉种子来源**：模型 → 状态机。生成器、tileset、调色板、模板、输出 schema **全部同一份代码**。
- **决策**：
  1. **抽出 `AssetForge`**：地图生成（`MapForge`：模板拼接 + Wang tiles + 连通性校验）、背景合成（Canvas 分层：天空/远景/地面/天气/时间色调 + 调色板锁定）、剧情生成（文法 + 状态机 + 因果规则），做成**平台无关 TS 模块**，主机 sidecar 与设备 `forge.worker` 共用。
  2. **端侧三档产物**（详见 §10.7.3）：
     - **地图场景**：状态机出种子（时间/天气/刚发生的事件）→ `MapForge` → 场景 JSON。**真生成**，与主机档同质量下限。
     - **小剧情**：文法生成 30–80 字（模板 × 人物状态 × 因果规则），带事件锚点。不是 LLM，但**有结构、有前因后果**。
     - **背景图**：Canvas 分层合成 960×540 → WebP。**是"合成"不是"AI 出图"**，端侧不跑任何扩散模型。
  3. **质量分层标记**：所有产物带 `tier: host | edge` 与 `origin`（`forge-procedural` / `forge-grammar` / `cc0:<源名>`）。显现背景**优先 host**，无 host 才用 edge；GUI 可一键"只看主机资产"。
  4. **零 token 是默认，云端轻写是可选**：程序化路径 **token = 0**（这是承诺，可审计）；设备有网时可选用受限 key 调云端写更长的剧情，**默认关**，日 ≤2k output（R24）。
  5. **生成前置自检闸门**：连通性 / 空白率 / 调色板对比度 / 分辨率下限，不达标丢弃重试 ≤2 次（R23）。
  6. **资源约束写死**：端侧内存增量上限 60MB → **100MB**（含 forge 峰值）；产物配额 ≤500MB，LRU 淘汰；日写入 ≤50MB 且批量落盘（R25，eMMC 寿命）。
  7. **不抢生活 tick**：`forge.worker` 与 `life.worker` 分离；forge 只在息屏/低帧率时段跑，任务切片 ≤5s 可中断；life tick P95 ≤8ms 不许被拖累（A16）。
- **后果**：
  - 端侧从"续经历"升级为"续经历 + 产轻资产"，主机不可达数天也有新场景/新剧情/新背景可看 → A16 专测。
  - R20 的性质从"风格分裂"变成"质量落差"，对策从"禁止"变成"共用生成器 + tier 标记 + 可隐藏"。
  - M6 增加 `MapForge`（M6-T7）；M11 增加 T17–T21；M11 工期 4 周 → **4.5 周**。
  - 新增 A16、R23/R24/R25；A12 端侧内存阈值 60 → 100MB；README 与 §1/§2/§3/§10 同步。
  - **明确不做**：端侧不做 LLM 对话、不做 TTS、不跑扩散模型出图。这三条不因本条 ADR 放开。

### ADR-014 总观 2D 场景不自研引擎：借格式、借算法、只写粘合层（v0.18）

- **日期**：2026-11-10
- **状态**：已接受（渲染后端待 M6-T10 实测定稿）
- **背景**：需求方提出"上帝视角 2D 地图 + 人物位置有没有现成开源可借鉴，不能重复造轮子"。复查发现原设计有**两处实质缺口**：
  1. **场景格式与人物移动根本没选型**——§4 只写了"场景 JSON schema 定义"（自造）和"tilemap 渲染层"，**位置表示、寻路、移动插值一个字都没有**；
  2. **§10.4 用 `state:overview` 5s 快照承载位置**，这在实现上必然导致小人在屏幕上瞬移。
- **调研结论（详见 §2.6）**：
  - **`pixel-agents`（MIT）** 做的正是"把 agent 在干什么画成像素小人在房间里走动"——与总观的诉求同构，且是 **Canvas 2D + BFS + 角色状态机 + 家具 manifest + 布局编辑器**；
  - **`ai-town`（MIT）** 给出了**位置与移动的正确定模**：`moveTo` 是 RTS 式"只给目标"，位置＝`position + orientation + speed`，用历史缓冲存每 tick 快照、客户端回放；
  - **`LDtk`（MIT）** 是比自造 schema 更好的选择：IntGrid 层就是寻路要的 grid，auto-layer 免自研 autotile，官方 schema 让程序化生成合法 JSON 很容易；
  - **WorkAdventure 是 AGPL-3.0 + Commons Clause → 代码禁用**，只能看产品形态。
- **决策**：
  1. **地图格式用 LDtk JSON**，`MapForge` 输出**同一份格式**——人工编辑与程序生成共用一个 schema，不自造（M6-T2/T11）。
  2. **运行时渲染改为"构建期烘焙分层 PNG + Canvas 2D 合成"**，`@pixi/tilemap` 降为备选并锁版本；**总观态不初始化 WebGL**（M6-T3/T4）。
  3. **位置与移动**：`PathAgent`＝网格 BFS 寻路 + 位置外推 + 状态机，照 ai-town 的定模；`moveTo` 事件式下行，`state:overview` 只做 `pos_checksum` 纠偏（M6-T8）。
  4. **寻路不引重依赖**：优先移植 pixel-agents 的 BFS（约 60 行），需要 A* 再引 `easystarjs`（MIT，7KB）。
  5. **素材建台账**：`docs/ASSETS-LICENSE.md` + CI 校验，CC0 优先，CC-BY-SA 慎用（M6-T9，R28）。
- **后果**：
  - **否定 ADR-005 的一条推理**："与 Live2D 共用 WebGL context 不增加内存"在**两态互斥**前提下不成立——两态不同时驻留，共用没有收益，反而让总观白背一个 WebGL 上下文。总观走 Canvas 2D 对 2GB 与 A14 冷启动是净收益。
  - 依赖面变窄：主路径 **0 渲染依赖**（Canvas 2D 是浏览器内建），**0 寻路依赖**（BFS 自备），最坏情况才引 2 个小型 MIT 包。
  - **代价**：动态 tile 变化需重新合成该层（≤120ms），不能只改一块 tile；接受，因为变化频率是"一天几次"。
  - M6 任务重排：T2/T3/T4 改写，新增 T8/T9/T10/T11，工期 2 周 → **2.5 周**；新增 R26/R27/R28。
  - 场景生成的产物契约统一为 LDtk JSON → `AssetForge`/`MapForge`/主机档模型生成的**输出格式只剩一种**，少一层转换。
  - **v0.22 修订**：本 ADR 决策 5 与调研结论中「WorkAdventure 代码禁用 / CC-BY-SA 慎用 / R28 防御式筛选」的**前提（商业发行）已被 ADR-015 撤销**；技术选型（LDtk / Canvas 2D / `PathAgent`）不变。

### ADR-015 项目定位为非商用开源，许可策略从「防御式禁用」改为「登记 + 致谢」（v0.22）

- **日期**：2026-11-10
- **状态**：已接受（项目级约束，与 §1.1 三条显示约束同级）
- **背景**：此前 v0.18–v0.21 的一系列许可结论都隐含一个**从未被明确写出的前提**——「本项目将来会商业发行」：
  - §2.6.1 / ADR-014：WorkAdventure 是 AGPL-3.0 + Commons Clause → **一行代码都不能进**；
  - §2.6.5 / R28：CC-BY-SA / AGPL 素材一律排除，怕「商业发行时被迫开源或下架」；
  - §9.12 / M7-T10：WakeTrace 是 PolyForm Noncommercial → 需要「买商用授权 vs 自研轻量版」决策；
  - R6：Live2D 样例模型「商用授权受限」。
  需求方 v0.22 明确指出：**「我们的项目不涉及商用，目标是开源的，不用在意被追责」**。
- **决策**：
  1. **项目定位定稿**：非商用（不销售、不以服务形式对外提供）、开源发布；自身许可证 MIT / Apache-2.0 待 M2 定稿。
  2. **许可不再是否决项**：选型只看观感、体积、集成成本。AGPL / Commons Clause / CC-BY-SA / PolyForm NC 不再自动排除。
  3. **台账保留但改目的**：从「防商业下架」改为「不漏登记、尊重上游」。`docs/ASSETS-LICENSE.md` + `scripts/check_assets_license.py` 继续存在并实跑。
  4. **保留两条工程约束**（许可证自身要求，非风险焦虑）：复制 AGPL 代码须让项目许可证兼容；用 CC-BY-SA 衍生美术须署名 + 同等开放。
  5. **若定位改为商用，本 ADR 必须重新打开**，上述被取消的决策（M7-T10 等）全部恢复。
- **后果**：
  - WakeTrace **PolyForm NC 1.0.0 可直接使用**，M7-T10 取消（§9.12 / §4 / §8.15）。
  - WorkAdventure 代码不再绝对禁用；当前仍无引入需求（§2.6.1 / §2.6.6）。
  - LDtk 样例的 CC-BY-SA 4.0 不再是禁区；因观感不适配仍不搬（§2.6.5）。
  - R6 / R13 降级；**R28 由「高影响 / 高概率」改写为「低 / 低」并改名「素材漏登记」**；新增 **R30** 防「开源＝零义务」误读；R29 结论不变（正式版不自绘美术）。
  - ~~**直接解锁 v0.22 交付**：正式引入两套 Kenney CC0 图集，做出三版观感对照 C 块~~ **v0.23 撤销**：该 C 块观感被需求方否决并重做（§2.6.8 / ADR-016）；「许可解锁」本身成立，但**不等于观感合格**。台账从「未开始」变为「已建立」结论保留。
  - 不影响任何显示/世界模型口径（§10）、LLM 云端路线（ADR-008）、端侧自治（ADR-011/013）。

### ADR-016 素材版重做：直接用上游设计好的地图，不做运行时瓦片拼装（v0.23）

- **状态**：已接受（v0.23，2026-11-10）。
- **背景**：v0.22 三版对照的 C 块用 Kenney CC0 瓦片硬套 B 版书房地图，需求方指出「效果还没有程序化美术好」；复核截图确认属实（§2.6.8）。曾尝试 5 版小修（换地板瓦片、改成套家具块、按 B 版构图逐件替换）均失败，根因是该图集为室外 / 建筑包、缺室内木地板，且缺少地图设计。
- **决策**：
  1. **不自绘，也不硬拼**——正式版总观的场景直接取上游已设计好的地图（`ai-town` `tilemap.json` 三层烘焙 / 未来 LDtk 导出），运行时只 `drawImage` 合成，不写「瓦片编号 → 网格」的通用映射。
  2. **角色用成套多帧精灵**（`32x32folk.png`，4 方向 × 3 帧），不再用单帧立绘翻转模拟。
  3. **素材与地图同批选定**，风格统一由上游保证；若换风格，整包替换并重新登记台账（R31）。
  4. **定量指标不作观感背书**：色数、体积、`drawImage` 次数只用于性能 / 体积评估；观感以真机渲染 + 人工评审为准。
  5. 许可仍按 ADR-015「登记 + 致谢」执行，MIT 原文与上游美术致谢随包保留。
- **后果**：
  - 正面：C 块场景 **0 行自绘代码**、裁片 48 色统一调色板、角色 4 方向多帧；`scripts/bake_aitown_map.py` 可离线复现。
  - 待办：C 的碰撞层与 A/B 家具未对齐（观感对齐物），正式版须由 LDtk 统一导出（M6-T11）；庭院主题与 A/B 书房主题不同，三版只共享 26×15 网格与 `PathAgent`。
  - 撤销：v0.22「C 颜色最少、文件最小却最好看」结论及本 ADR-015 中「直接解锁 Kenney C 块」表述作废。
- **若将来改为商用**：与本 ADR 无关（ADR-015 需重开），但素材许可仍须按台账复核。

### ADR-017 记忆/向量检索定稿：三个标准件，不引入"大而全"的记忆产品（v0.24）

- **日期**：2026-11-10
- **状态**：已接受；**收口 ADR-004 的「备选二选一」与 M8-T1**
- **背景**：§2.7.1 盘点后确认，长期记忆是 §2.2 全表唯一还挂着"二选一未定"的通用轮子，且 A9（回忆 7 天前事实）是硬验收。原 ADR-004 只写了「不依赖 Letta，走 Agent 接口自建」，留下 `mem0` 与 `sqlite-vec` 两条路。
- **决策**：
  1. **落地基线 = `asg017/sqlite-vec`（Apache-2.0 / MIT）+ SQLite 内建 FTS5 + `qdrant/fastembed` 的本地中文 embedding**（`BAAI/bge-small-zh-v1.5`，512 维 / 约 90MB / MIT / ONNX Runtime 无 torch）。三者组装成单个 `memory.db`，装在 PC 的 `orchestrator` sidecar，**设备端零新增依赖**。
  2. **不整套引入 `mem0ai/mem0`**：其 `add()` 每次调 LLM 抽取事实、默认 Qdrant + OpenAI，违反「单一安装包」（C1）与「日 output 8k 硬顶、检索 0 API 费用」（C2）。只借其抽取/更新/去重流程，并改成**会话末批量 + 规则预筛**。
  3. **不引入 `getzep/graphiti`**：时序事实有效期 + 混合检索概念最贴，但强制图数据库。只借「事实带有效期、被取代而非删除」的建模（`supersedes` 字段）。
  4. **不作基线但记下 `tigerless-labs/agent-memory`**：Markdown 为唯一事实源 + 可重建索引 + 库内无 LLM 客户端，架构最贴合，但 2026-09 才建、0.1.0 无 release，成熟度不足以压 A9。其「索引可删可重建」理念被采纳。
  5. **检索融合**：`0.5×KNN + 0.3×BM25 + 0.2×0.5^(age/30d)`，`tier`（L0–L3）参与加权，L0 常驻块不衰减。设备端只收摘要 JSON（M8-T6 不变）。
- **理由**：这是唯一同时满足六条判据（C1–C6，§2.7.2）的组合；且 `mem_meta` 正文与索引解耦，任何索引换掉都不丢记忆（呼应 R32）。
- **后果**：
  - 正面：无额外服务、无 API key、无云端 embedding 费用；单文件可备份；`scripts/spike_memory_vector.py` 已实测融合管线（§8.17）。
  - 代价：PC 安装包新增约 60–100MB 运行时依赖 + 约 90MB 模型；**模型必须预置或离线导入**（R33，直连 HuggingFace 实测超时）。
  - 新增风险：R32（pre-v1 停更 / 暴力扫描）、R33（模型分发）、R34（中文 FTS5 退化）；E19 / E20 记录实测坑。
- **备选（若日后规模或维护情况变化）**：换回纯 SQL 暴力扫描、或改 `sqlite-lembed` 把 embedding 也放进 SQLite；两者都不改 `mem_meta` 正文结构。
- **与 ADR-015 的关系**：本项目非商用开源，许可不是否决项；本次仍把 Apache-2.0 / MIT 与模型 MIT 登记在 §2.2 与 §2.7.4，是尊重上游，不是防御式筛选。

| E11 | **后端 VAD 会把 torch 拖进来** | `vad_model: silero_vad` 需 `torch`（CPU 版 200MB / PyPI CUDA 版 2.5GB），但前端只用 `mic-audio-data`、从不发 `raw-audio`，后端 VAD 根本不被调用 | 设 `vad_model: null`，靠前端 `silero_vad_v5.onnx`；省掉整个 torch 依赖 |
| E12 | 内置 MCP 服务器连不上 | `mcp_enabled_servers: ["time","ddg-search"]` 启动时 MCPC 报 `TypeError: unsupported operand ... float and timedelta` | M0 阶段先置空数组，WakeTrace 在 M7 接 |
| E13 | **TTS 流式开关必须关** | `gpt_sovits_tts.streaming_mode: 'true'` 时，GPT-SoVITS 返回的 WAV 头 `data` 长度为 0（占位），pydub/ffmpeg 解析出 **0 帧**，OLVT 报 `max() iterable argument is empty`，整句变静音。且 OLVT 适配器用 `requests.get` 一次性收全，**根本不消费 chunk，流式没有任何加速收益** | 设 `streaming_mode: 'false'` |
| E14 | **50 系上 CUDA graph 崩溃** | GPT-SoVITS `api_v2` 默认 `parallel_infer=true` + `use_cuda_graph=true`，在 RTX 5070 上触发 `CUDA error: operation not permitted when stream is capturing`，服务进入 `'NoneType' object has no attribute 'model'` 的坏死状态，须重启 | 请求显式带 `use_cuda_graph=false`（已在 OLVT 侧打补丁） |
| E15 | **ffmpeg 缺失的隐蔽后果** | 不只 pydub 告警：音频被解析成 0 帧，表现为 `max() iterable argument is empty`，看起来像 TTS 故障，实际是解码故障 | 装 `imageio-ffmpeg` 取自带二进制，复制为 `tools/bin/ffmpeg.exe` 并加 PATH（免装系统 ffmpeg，便于打包） |
| E16 | **中转站三个隐蔽行为** | ① 带 `stream_options={"include_usage":true}` 直接挂死到超时（100% 复现），易误判为模型/网络故障 ② 默认开思考，`max_tokens=50` 时 `reasoning_tokens=50`、正文为空 ③ `reasoning_effort="none"` 有效 | 探测脚本不带 `stream_options`；请求固定关思考 |
| E17 | **.bat 用 LF 换行会断在 `goto`** | 脚本由工具生成，默认 LF 无 CRLF。cmd 在纯 LF 批处理里做标签跳转（`goto :wait_gsv`）会报「系统找不到指定的批处理标签」并中止，表现为「先弹 TTS 窗口，然后脚本秒退，后端根本没起」 | 一律写 CRLF；并去掉 `goto` 循环，改用 PowerShell 自带重试上限的轮询 |
| E18 | **引入素材反而比自绘更难看** | v0.22 的 C 块用 Kenney 地牢 / 室外 16×16 瓦片硬套书房：地板成橙色条纹壁纸、家具成格子墙、地毯成红白棋盘、角色只剩单帧小脑袋。根因是**瓦片当贴图平铺 + 素材风格不匹配 + 无地图设计 + 无统一光照**，不是素材粗糙，也不是许可问题；期间 v2–v6 五版小修均失败 | 撤销「色数 / 体积＝观感」的错误结论（§2.6.8）；改用 `ai-town` 官方 `tilemap.json` 烘焙地图 + 4 方向 3 帧精灵；定量指标不得代替人工看图（ADR-016） |
| E19 | **中文 FTS5 会静默 0 命中** | 默认 `unicode61` 把整句当一个 token；换 `trigram` 后仍有两条硬约束：① MATCH 串必须 ≥3 字符（"京都" 0 命中）② 必须是正文**连续子串**（"京都枫叶" 在 "京都看枫叶" 里也 0 命中）。第一次 spike 的全文路完全空转，融合结果看似正常，实际只剩向量 + 时间衰减 | 固定 `tokenize='trigram'`；查询切成 ≥3 字片段做 OR；全文只占融合权重 0.3，语义由本地 embedding 兜底；上线前用中文样本验字面召回（R34） |
| E20 | **本地 embedding 模型下载不下来** | `fastembed` 首次加载 `BAAI/bge-small-zh-v1.5` 需从 HuggingFace 拉约 90MB ONNX；本机直连三次超时，镜像两轮 240s/300s 均卡在最后一个文件。表现为抛 `Could not load model ... from any source`，记忆功能首次启动直接不可用 | 模型随安装包预置或由 M2 模型管理器离线导入（与 ASR int8 同机制，E8）；启动校验本地存在性；缺模型静默退回纯 FTS5 检索，不报错（R33） |

### 8.5 LLM 走 API 的架构后果

2026-11-09 决定：**LLM 预设走云端 API**（OpenAI 兼容中转站），不在本地跑。

理由：RTX 5070 12GB 需同时承载 GPT-SoVITS（约 4–5GB）与本地 LLM（9B Q4 约 5.5GB + KV cache），叠加 Windows 显存开销后余量不足，必然引发换页或 OOM。

| 后果 | 说明 | 归属 |
|---|---|---|
| **断网即失语** | 离线降级从"可选"变"必须"：本地预设短语 + Live2D 待机 + 记忆摘要兜底；LLM 5s 无响应必须切话术 | M6 |
| **工具调用能力受中转站约束** | `mcp_plus` 依赖 function calling，中转站不支持则 MCP 接不了 WakeTrace | M7 |
| **备选路径** | 绕开 MCP，由编排器把 WakeTrace 事件直接拼进 system prompt——少一跳、低延迟，且权限归位 | M7 |
| **密钥存储** | `conf.yaml` 已 gitignore；打包须排除该文件，改由 GUI 写入 `%APPDATA%/DigitalHuman/` 并做 DPAPI 加密 | M2 |
| **成本控制** | 主动醒来会频繁触发调用，需给 WakeTrace 设每日预算上限 | M7 |

### 8.8 LLM 中转站延迟问题（M0 唯一未达标项）

同一提示词、同一模型 `deepseek-v4.1-flash`、关闭思考后连续实测：

| 场景 | 首字延迟 | 整句 |
|---|---|---|
| 复用连接的简单提示（第 2、3 次） | **1.10s / 1.30s** | 1.50–1.68s |
| 冷连接首次 | 2.10s | 3.04s |
| 完整人设 + 工具提示 | 12.7s | 14.5s |
| 连续压测中的一次 | 4.99s | **35.1s** |

**问题：延迟波动 1s → 35s，不可预测。** 该中转站（`codex.mintcat.work`）面向编码代理场景，无实时性承诺；同一 key、同一模型在几分钟内可从 1.1s 劣化到 12.7s。

对虚拟人而言这是硬伤：用户说完话后 5 秒无回应就该判为故障。**需要更换 LLM 接入，或增加降级策略。**

**23:40 复测（仅测 deepseek 系，未碰任何其他型号）**

| 测试 | 结果 |
|---|---|
| 非流式 ×8（单次上限 12s） | **7 次超时（12.2s）**，1 次成功（9.9s） |
| 流式 ×3（单次上限 25s） | **2 次 25s 零字节**，1 次 3.0s 出首包 |

| 官方端点 | `api.deepseek.com` 从本机可达（返回 401，仅缺 key），握手 0.24s |

成功率约 **12%（非流式）/ 33%（流式）**，成功时延迟 3–10s。这已不是"延迟偏高"，而是**不可用**。R10 由高风险升级为阻断项：不换官方 key，M3 之后的交互调试都没有意义。

**新发现 E16（中转站三个隐蔽行为，排查时极易误判）**

| 现象 | 实测 | 后果 |
|---|---|---|
| 不认 `stream_options={"include_usage": true}` | 带上即挂死到超时，100% 复现 | 会被误判成"模型不可用/网络坏"；探测脚本已移除该参数 |

另：该站返回的 `model` 字段固定为 `deepseek-flash`，usage 带 DeepSeek 原生字段 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` / `cached_tokens`，证明上游确实是 DeepSeek 官方——**换成官方直连是近零改动**，同时让 §8.11 的缓存估算可被真实校准。

### 8.10 M0 结论

**架构可行。** PC 端软件化路径（Tauri + sidecar）没有技术阻塞。全链路（LLM → TTS → 音频 + 口型）已实测跑通。

**最大风险已从"技术可行性"转为"资源获取"**：模型体积 + 网络带宽。这直接影响 M2（单包分发）的设计——必须做国内镜像 + 断点续传 + 分层下载，否则用户装不上。

### 8.11 DeepSeek 官方路线消耗与费用估算（2026-11-09）

**实测基准**（`scripts/measure_tokens.py`，用正式规模的中文人设实际调用并读 `usage`，非经验估算）：

| 项 | 规模 | tokens |
|---|---|---|
| 人设 prompt | 655 字 | 约 300 |
| Live2D 表情提示（含 24 个 emokey） | 706 字 | 约 313 |
| **基础 system 合计** | 1363 字 | **613** |
| MCP 工具提示 | 1689 字 | 374 |
| 工具 schema（一个 WakeTrace 风格工具） | 307 字 | 301 |
| **完整 system（接 WakeTrace 后）** | 3359 字 | **约 1300** |
| 单轮用户输入 | 21 字 | 15 |
| 单轮助手回复 | 66 字 | 94 |

换算率：中文约 **2.2 字 / token**。

**官方计价**（元 / 百万 tokens，2026-11 官方页面）。峰时为北京时间工作日 9:00–12:00、14:00–18:00，其余时段（含周末、法定节假日全天）为空闲，闲时价为峰时半价：

| 模型 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
|---|---|---|---|
| `deepseek-flash` | 0.02 / **0.04** | 1 / **2** | 4 / **8** |
| `deepseek-v4-pro` | 0.15 / **0.30** | 4.5 / **9** | 13.5 / **27** |

**计费口径**：OLVT 的 `basic_memory_agent` 每轮全量重发 system + 全部历史且无截断（源码已确认），因此输入随轮次线性增长（60 轮后单轮输入约 8k tokens）。但 DeepSeek 自动前缀缓存生效时，**每轮只有「上一轮回复 + 本轮新输入」约 115 tokens 未命中**，system 与旧历史全部按命中价计——命中价仅为未命中价的 2%，所以长历史几乎免费。

**月费估算**（`scripts/estimate_cost.py`，连续会话、缓存生效）：

| 场景 | 轮/天 | 输入 k/天 | deepseek-flash 峰时 | flash 闲时 | v4-pro 峰时 |
|---|---|---|---|---|---|
| 轻度陪伴 0.5h/天 | 20 | 48 | **¥0.75** | ¥0.37 | ¥2.99 |
| 中度 2h/天 | 60 | 282 | **¥2.26** | ¥1.13 | ¥9.53 |
| 重度常开 8h/天 | 150 | 1480 | **¥6.47** | ¥3.23 | ¥30.31 |
| 演示/展会 12h/天 | 300 | 5548 | **¥15.96** | ¥7.98 | ¥83.57 |

**最坏情况**（每轮缓存都失效，如会话间隔数小时、多设备并发、频繁重启）：flash 峰时 20/60/150/300 轮对应 **¥3.35 / 18.33 / 92.41 / 340.06 每月**；pro 在 300 轮时达 ¥1522/月，不可取。

**敏感度**（中度 60 轮/天，flash 峰时）：回复从 100 → 300 tokens 使月费 ×2.8；人设扩到 3000 tokens 仅 ×1.1（只在首轮未命中）；**开思考模式（每轮 +800 思考 tokens）×6.1**；切 pro ×4.2。

**工程结论**：

1. **成本不构成约束**，个人日常使用月费在个位数人民币量级；真正要管的是延迟（R10），不是费用。
2. **唯一显著的成本杠杆是思考模式**。官方 V4 默认 `thinking=enabled` 且 `effort=high`，思考 token 按输出价计费。必须在请求里显式关闭：`reasoning_effort="none"`，或 `extra_body={"thinking": {"type": "disabled"}}`（现有 `OLVT_LLM_EXTRA_BODY` 补丁可直接承载）。
3. **接 WakeTrace 前必须关思考的第二个理由**：带 `tools` 参数时，官方要求历史轮次的 `reasoning_content` 全部回传，否则返回 **400**；OLVT 不保存也不回传该字段。所以 M7 接 MCP 的前提是关思考，否则整条工具链起不来。
4. **供应商切换成本极低**：官方与中转站同为 OpenAI 兼容，改 `base_url` / `model` / `llm_api_key` 三行即可；模型名用新的 `deepseek-flash`（旧 `deepseek-chat`/`deepseek-reasoner` 已于 2026-07-24 停用）。
5. **仍需给 WakeTrace 设日调用上限**（M7）：主动搭话是"无人值守"调用，若出现循环唤醒，成本与体验会同时失控；建议日上限 200 次 + 单日 token 预算告警。
6. **记忆向量检索不产生 API 费用**：官方无 embedding 接口，方案本来就是本地 embedding（M8），这条路反而更省。
7. **M8 记忆注入必须放末尾**：前缀缓存对"中间插入"零容忍——若每轮把检索到的记忆拼进 system prompt 开头/中部，system 之后的所有内容全部失效，每轮退化为全量未命中，中度使用月费从 ¥2.26 跳到 ¥18.33（约 8 倍）。因此记忆摘要应作为**历史之后、本轮用户输入之前的消息**注入，或只在会话开场注入一次。这与"记忆要自然使用"的设计不冲突，但决定了注入点的实现位置。

|---|---|---|---|---|---|
| 1 | 0.86s | 0.171s | 0.323s | 0.381s | 0.05 |
| 4 | 0.87s | 0.067s | 0.123s | 0.139s | 0.02 |

**结论**：

- 识别率 3/3 全对，**ITN 生效**（「三点半」→「3点半」、「十点」→「10点」），可直接喂给 LLM 做时间理解。
- PC 上 ASR 是零成本环节：4 线程 RTF 0.02，3 秒话说完 0.07 秒出文本，对首字延迟几乎没有贡献。
- 模型加载仅 0.87s（int8 + CPU），不需要预热驻留策略。
- **外推到 RK3566**：4×Cortex-A55 单核约为桌面核的 1/5–1/8，4 线程 RTF 预计 0.1–0.16，3 秒语音约 0.3–0.5s，仍可接受。此为估算，非实测（M4 必测）。
- **未覆盖的风险**：测试音源是干净合成音。真实场景有远场、回声、方言、口音，识别率必然下降。设备端需用真人录音复测，并考虑加 hotwords（配置项已具备）。

### 8.13 HTTPS / WSS 网关验证（设备麦克风前置，2026-11-10）

设备浏览器调用 `getUserMedia` 要求 secure context，`http://局域网IP` 直接不可用。验证方案：自签证书 + TLS 终止网关（8443 → 12393）。网关做纯字节转发，因此同时覆盖 HTTP 与 WebSocket（WS 只是 HTTP Upgrade）。

| 项 | 结果 |
|---|---|
| 证书 | 自签 RSA2048，SAN 含 `IP:192.168.8.51`、`IP:127.0.0.1`、`localhost`、`dhvw.local` |
| HTTPS 首页 | `https://127.0.0.1:8443/` → **200**，TLS 握手 12ms |
| 局域网访问 | `https://192.168.8.51:8443/` → **200** |
| 证书链校验 | 用 `--cacert` 指向自签证书后 **200**（不是靠 `-k` 跳过校验，说明链路本身可信） |
| WSS 升级 | `wss://127.0.0.1:8443/client-ws` 55ms；`wss://192.168.8.51:8443/client-ws` 6ms |
| 双向消息 | 发送 `fetch-configs` 能收到 `group-update` 回包，通道可用 |
| 静态资源 | 1.9MB JS：http 12.5ms / https 17.3ms；8.2MB Live2D 纹理经网关 45ms |

**结论**：设备麦克风的 secure context 前提已成立，剩下只是把自签证书装进设备信任库（M4）。网关在本机几乎无开销。

**注意**：`scripts/tls_gateway.py` 目前是验证脚本——单连接无并发上限、无优雅退出、证书路径靠参数传入。M3 要换成正式实现（证书生成/续期、并发限制、随主程序启动、崩溃自恢复）。

### 8.14 WakeTrace 主动性验证（v2.1.0，2026-11-10）

**能跑通的部分**

| 项 | 结果 |
|---|---|
| 部署形态 | Python 3.12 独立 venv，单进程同起 API + MCP + Web + 调度器，8765 端口，启动 3s 内 ready |
| Windows 依赖 | **缺 `tzdata` 直接启动失败**（`ZoneInfoNotFoundError: Asia/Shanghai`）；装 `tzdata` 后正常。Linux/Docker 无此问题 |
| 模型连通 | `POST /admin/tests/model` → `ok`，2.8s |
| 手动唤醒 | `force` 下 6.4s / 6.6s / 8.6s，产出 200–300 字正文，质量高 |
| 打扰控制 | 不加 `force` → `outcome=skipped:minimum_interval`，1.4s 返回，**未调模型**（策略在 LLM 之前拦） |
| 调度 | 自动排 `next_wake_at`，落在配置的 30–120 分钟区间内 |
| REST | `/health` `/status` `/world/setup` `/world/events` `/world/timeline` `/wake` 全部可用 |

**三个硬伤（都实测复现）**

1. **MCP 工具调用不可用**。`list_tools` 正常返回 10 个工具，但 `call_tool` 必失败：mcp 2.3.0 客户端报 `404 Not Found`（服务端日志显示请求被发到 `POST http%3A//127.0.0.1%3A8765/mcp`，URL 被整段编码成路径）；换成与它同版本的 mcp 1.30.0 客户端，报 `Session terminated`。两端版本都试过，属服务端 streamable HTTP 会话管理缺陷，不是配置问题。
2. **没有 webhook，通知送不出来**。可用通知器只有 `ConsoleNotifier` 与 `WebPushNotifier`。未配 VAPID 时，模型给出 `outcome=message` 也会因 `delivery_failed` 降级成 `trace`——它想说，但没地方送。
3. **判定极保守**。3/3 ambient 场景全部 `outcome=trace`。提示词原文写着「静默是有效结局」「生活事件可以只被看见，不必每次都转化为给用户的消息」。靠它自己驱动主动搭话，实际基本不会开口。

**另外两个问题**

- **时区 bug**：提示词只把 `seed.occurred_at`（UTC ISO 串）交给模型，没有本地时区也没有时段上下文。北京时间 12:36 的一次唤醒，它写成「凌晨四点半的屏幕光」。出现在用户面前就是硬伤。
- **两套脑子**：它是独立 LLM 循环，有自己的 prompt 与记忆，与 OLVT 的对话记忆不共享（只靠 `fact` 传一句）。长期会分裂成「聊天里的绫」和「生活里的绫」。

**决策（M7-T1 定稿）：不走 MCP，走 REST 旁路**

- 编排器定时拉 `/world/timeline`（或直读它的 SQLite），取新的 `fact` / `share`；
- 把摘要作为上下文注入 OLVT **历史之后、本轮输入之前**（遵守 §8.11 第 7 条，否则前缀缓存全失效）；
- **是否开口由我们的 A8 策略决定**（≤2 次/小时、23–7 静默）。WakeTrace 只负责「生成生活」，不负责「是否打扰」。

理由：一次绕开 MCP 坏、通知弱、判定保守三个缺陷；同时省掉每轮请求里的工具 schema（301 tokens/轮）。

**许可**：PolyForm Noncommercial 1.0.0，**商用须授权**。两条路：① 换自研轻量版——它的 schema 极清晰（`seed → fact / content / share / residue / next_wake`），照着实现成本不高；② 谈授权。个人自用无碍。

**成本**：每次唤醒 = 一次额外模型调用（约 2k 输入 + 300 输出），flash 价约 ¥0.002，默认 15 次/天封顶，月成本可忽略。但单次 6–8 秒，**不能当实时触发器用**。

## 9. M7 主动性接入设计（WakeTrace → 表达链路）

> 目标不是"让虚拟人会说主动的话"，而是"让同一个人有连续的内心生活"。
> 本章是 M7 的实施手册，所有结论均有 §8.14 / §8.16 的实测支撑。

### 9.1 三条设计原则

1. **生活流与对话流分离，但共用一个大脑。** WakeTrace 只负责"发生事、产生心理活动"，不负责"开口"；开口永远是 OLVT 这一侧、这一个角色说的。任何让两套 LLM 各自说话的设计都会分裂人格（§8.14「两套脑子」）。
2. **沉默也是一种状态，而且比说话更重要。** WakeTrace 绝大多数周期是 `trace`（不想说话）。这些条目不丢弃，转为**被动上下文**，在她下次听你说话时影响语气。这是"像有自主意识"的主要来源，成本几乎为零。
3. **开口权在我们手里，且必须在调用 LLM 之前决定。** 不让模型自己决定"要不要说"：一次主动调用已花 5 秒和一次 token，再让它输出"我选择沉默"只会更难收场（还可能被 TTS 念出 `[silent]`）。

### 9.2 组件与数据流

```
WakeTrace :8765                     本机：编排器（①②③⑤）+ OLVT :12393（④ 必须在 OLVT 进程内）
┌────────────────┐   REST 轮询     ┌──────────────────────────────┐
│ 调度器          │◄───────────────│ ① LifeStream  生活流同步器    │
│  └ 唤醒周期     │                │    拉 /world/timeline         │
│     seed→content│  POST 事件     │    去重 / UTC→本地 / 落 life.db│
│     →share      │◄───────────────│ ⑤ Echo  回声写入              │
└────────────────┘                │                              │
                                  │ ② ContextComposer 上下文合成  │
                                  │    → 被动注入块 / 主动块      │
                                  │                              │
                                  │ ③ A8Gate  打扰闸门（先决断）  │
                                  │                              │
                                  │ ④ ProactiveSpeaker 主动发言   │
                                  │    POST /dhvw/proactive       │
                                  │    → 复用设备连接合成音频      │
                                  └──────────────────────────────┘
```

| 组件 | 职责 | 交付形态 | 备注 |
|---|---|---|---|
| ① LifeStream | 增量同步时间线、字段归一、本地落库 | `orchestrator/life_stream.py` | 游标 = 最大 `id`；`cycle_id` 唯一键去重 |
| ② ContextComposer | 生成两种注入块，控制 token 预算 | `orchestrator/context.py` | 与 M8 记忆**共用同一注入点** |
| ③ A8Gate | 决定 speak / inject-only / drop | `orchestrator/gate.py` | 决策全部落日志，A8 靠它验收 |
| ④ ProactiveSpeaker | 触发无输入轮次 | OLVT 内 `routes.py` 新端点 | **不能另开 WS 连接**，见 §9.5 |
| ⑤ Echo | 把"我说过什么"写回生活流与注入块 | `orchestrator/echo.py` | 解决人格连续性 |

### 9.3 数据契约（WakeTrace → 我们）

来自 `/world/timeline`，实测字段（2026-11-10，3 条真实记录）：

| 字段 | 含义 | 我们的用法 |
|---|---|---|
| `cycle_id` | 唤醒周期序号，单调递增 | 去重主键 |
| `created_at` | UTC ISO 串 | **必须转本地时间再注入**（§8.14 时区 bug） |
| `outcome` | `trace` / `message` / `skipped:<原因>` | 决定走被动注入还是可主动 |
| `requested_outcome` | 模型自己想干什么 | 与 `outcome` 不一致时说明被策略/投递拦了 |
| `notification_reason` | 被拦原因（如 `delivery_failed`） | 用于判断是否值得抢救 |
| `content` | 100–300 字内心活动，文学化叙述 | **不能原样注入**，只取具体事实，见下 |
| `share` | 只有 `message` 时才有，给用户的一句话 | 主动发言的种子 |
| `residue` | 情绪残留 | 作为语气参数，不进正文 |

真实样例（`cycle_id=1`，模型本想说话但投递失败）：

- `content`：「凌晨四点半的屏幕光把人的轮廓压得很扁。三个小时没起身……」（其中「凌晨四点半」是 bug，实际 12:36）
- `share`：「三个小时没动了。先站起来走两步，喝口水，再回来看屏幕——它不会跑。」

**转换规则（必须遵守）**

- `content` 是**观察者视角的散文**，直接塞进对话会让角色开始念旁白。只允许提炼成一句第三人称事实：「12:36，你把最后一版方案交出去，靠在椅背上松了一下。」
- 这条提炼**不再调 LLM**（省一次 5 秒），用规则：取 `share` 全文 + `content` 的**首个分句**，去除比喻句与"我不打算说话"这类元叙述。M7-T2 里用 20 条真实样本校准，误判就退化为「只注入 `share`」。
- `occurred_at` / `created_at` 一律 `zoneinfo` 转 `Asia/Shanghai` 后再格式化，禁止把 UTC 串交给模型。

### 9.4 两条注入路径（关键：位置固定）

| 路径 | 触发条件 | 注入内容 | 注入位置 |
|---|---|---|---|
| **被动**（默认，占 90%） | 用户说话/打字 | 近况块（最近 1–3 条生活事实 + 上次主动说过的话） | 历史之后、本轮输入之前 |
| **主动**（少数） | 闸门放行 | 生活片段块（含开口要求） | 作为 `ai-speak-signal` 的 `text` 载荷 |

**代码位置（已核实）**：`agent/agents/basic_memory_agent.py:242 _to_messages()`——先 `messages = self._memory.copy()`，再 `messages.append(user_message)`。注入点就在这两者之间，即：

```python
messages = self._memory.copy()
# [DHVW] 在此插入近况块（新的 user 消息，或并入 user_message 前缀）
...
messages.append(user_message)   # 本轮用户输入
```

**缓存纪律（§8.11 第 7 条）**：块**绝不能进 system**，也不能插在历史中间。放历史末尾时，每轮未命中量 = 上一轮 user+assistant + 本块 + 本轮输入 ≈ 200 tokens，与不注入时同量级；插进 system 中部会让整段历史每轮全量未命中（月费 ×8）。时间戳取整到 5 分钟，可进一步复用前缀。

**被动块格式**（实测生效，约 90 tokens）：

```
[你的近况 · 不是用户说的话]
现在：2026-11-10 13:05 周二
刚才 12:37：你把最后一版方案交出去，靠在椅背上松了一下，手机亮着没看。
你 12:50 说过：「这雨下得……连我都想偷懒了。」
——以上是你自己的经历和状态，融入语气即可；不要复述，不要说"我看到记录"。
```

**主动块格式**（实测生效，约 110 tokens）：

```
[生活片段 · 非用户输入]
现在：2026-11-10 13:02 周二，午后，外面在下雨。
你刚经历：从窗边回到桌前，玻璃上有一层水痕。
开口要求：1–2 句，口语，接着这个片段说；不要解释你在做什么，不要说"我注意到"，
不要提问式追问，不要提及记录或系统。
```

> 提示：**不要在块里给模型"可以沉默"的选项**。沉默由 ③ 在调用前决定（§9.1 第 3 条），否则会出现 `[silent]` 被 TTS 念出来的事故。

### 9.5 主动发言的投递路径（最容易踩死的地方）

**实测结论：`ai-speak-signal` 可用，但音频只会回到「发起该请求的那条 WebSocket」。**

- `websocket_handler.py:142` 用 `client_connections[client_uid] = websocket` 一对一绑定；服务端把 TTS 音频 send 回这条连接。
- 因此**编排器不能自己连一条 WS 去发 `ai-speak-signal`**。我实测时就是这么做的：文本和音频都回到了测试脚本，设备端一个字节也收不到；若复用同一个 `client_uid`，还会覆盖映射、并在断开时把设备连接一起清掉。

**定案：走进程内端点。**

```
POST /dhvw/proactive   {"text": "<主动块>", "client_uid": "<可选，缺省取唯一在线连接>"}
   → 取 client_connections[client_uid]
   → 复用 handle_conversation_trigger("ai-speak-signal", {...}, client_uid, ctx, ws, ...)
   → 正常经过 TTS / Live2D 表情 / 字幕，前端零改动
```

好处：① 前端不用改，stock 构建即可；② 能就地判断"用户正在说话"（`current_conversation_tasks` 活跃则拒绝）；③ TTS 失败可在同一处降级为文字气泡；④ 与 `ai-speak-signal` 原语义完全兼容（`skip_memory`/`skip_history` 保留）。

**已打补丁（补丁 3）**：`conversations/conversation_handler.py:35` 允许 `data["text"]` 覆盖固定提示词。原实现只会加载 `prompts/utils/proactive_speak_prompt.txt`（内容为英文 `Please say something that would be engaging...`），模型既不知道"为什么现在开口"，还会用英文答、脱离人设——实测两次均如此。补丁后同一通道返回中文、贴合事件、带 `[neutral]` 表情标签。

**M5 可选迁移**：自研前端后，可改由前端接收信号并在自己的 WS 上发 `ai-speak-signal`，服务端端点即可移除。当前阶段不必。

### 9.6 A8 闸门策略（可执行规则）

按顺序判定，任一不通过即 `drop` 或降级为 `inject-only`：

| # | 条件 | 动作 |
|---|---|---|
| 1 | 静默时段 23:00–07:30 | drop |
| 2 | 用户正在一轮对话中（任务活跃） | drop |
| 3 | 距上次主动 < 45 分钟 | drop |
| 4 | 本小时已 2 次 / 今日已 8 次 | drop |
| 5 | 设备离线或无在线连接 | drop（事件留作"见面聊"素材） |
| 6 | 最近 30 分钟无任何用户输入（ASR/文本/触屏） | inject-only |
| 7 | `outcome != message` 或 `share` 为空 | inject-only |
| 8 | 连续 3 次主动、5 分钟内无用户回应 | 该时段降频至 1 次/2 小时 |
| 9 | 首次安装 24 小时内 | inject-only（观察期） |

**状态机**：`IDLE → (新事件) → EVALUATE → SPEAK | INJECT_ONLY | DROP → COOLDOWN`

**决策日志**（`life.db: gate_log`）：`ts / cycle_id / decision / reason / user_replied_within_5m`。A8 的验收直接查这张表，不靠感觉。

### 9.7 人格连续性（两套脑子的补丁）

| 问题 | 解法 |
|---|---|
| 她说完就忘（主动轮 `skip_memory=true`） | 由 ⑤ 把"我刚说了什么"写进**下一次被动块**（`你 12:50 说过：「…」`）。零改动、可控、不污染历史 |
| 生活里的她 ≠ 聊天里的她 | 正向：生活 `content` → 被动块（已设计）；反向：每 N 轮或会话结束时把对话要点 `POST /world/events` |
| 重启后主动发言全丢 | 不做历史持久化，统一由 `life.db` + `echo` 表重建，避免 OLVT 历史出现孤儿 assistant 消息 |

> 反向写入是"她记得我们聊过"的关键，但依赖 M8 的抽取管线，**排在 M8 之后**做，M7 只留接口。

### 9.8 失败与降级

| 故障 | 现象 | 处理 |
|---|---|---|
| WakeTrace 掉线 | 无新事件 | 用最后事件做时间衰减；>6h 无事件则不主动；**对话功能完全不受影响**（fail-open） |
| LLM 超时（R10） | 主动轮失败 | 不重试（避免 5s + 5s 叠成 10s）；30 分钟后换下一条；连续 2 次失败当日停主动 |
| TTS 失败 | 无音频 | 降级为文字气泡 + 表情，不静默 |
| 设备离线 | 无连接 | 不消耗 LLM；事件标记 `pending_reunion` |
| 时钟漂移/时区 | 时间说错 | 统一 `Asia/Shanghai`，注入前断言年份与小时合理（避免"凌晨四点半"重演） |

## 10. 显示态与世界模型（总观常显 / 显现需主机 / 世界双档·主机优先）

> **v0.16 修正**：v0.15 把"连不上主机时降为端侧轻型"误读成"取消主机档、离线优先"，本版纠正。
> **主机世界的要求不变**——能连上主机核心就用核心机干活（产资产）；只有**连不上主机**时才降为端侧轻型档，用设备现成硬件把日子接着过下去。
> **v0.17 修正**：端侧档**不是"只写日志"**——它也能产资产（剧情 / 场景 / 背景），只是低一档（详见 §10.7.3、ADR-013）。理由很硬：主机档的生产本来就是"模型出**种子** → 本地**确定性生成**"，**生成器一直在本地**，端侧只需换种子来源。
> 三条不可违反的约束：
>
> - **总观常显**：默认态，任何情况下都要出画面（主机不在、断网、PC 从未装过）。它是所有降级的落点，**必须端侧可渲染**。
> - **显现需主机**：对话要 LLM + TTS，主机不可达就**不能进入显现**，不提供"降级显现"。
> - **世界双档、主机优先**：只要主机可达且满足与门，就走**主机档**（GPU + 云端 token 产资产）；主机不可达才用**端侧档**（CPU + 本地 `AssetForge` 续经历**并产轻资产**，程序化路径零 token 零 GPU）。
>
> 另有一条容易搞混的区分：**"主机可达"与"设备有网"是两件事**。设备端本身可以联网（4G/家用 WiFi），端侧档并不是"断网模式"，只是"用不上主机"。

### 10.1 四个维度与合法性矩阵

| 维度 | 取值 | 谁看得见 | 决定什么 |
|---|---|---|---|
| **显示态** | 总观 / 显现 | 屏幕上的一切 | 设备内存、Live2D 是否加载、是否需要主机 |
| **主机可达** | 可达 / 不可达 | 角标一个点 | 显现能否进入、世界走哪一档、事件能否回流 |
| **设备网络** | 有 / 无 | 不显示（仅菜单） | 端侧档能否校时 / 更新资源 / 可选云端增强；**与主机可达无关** |
| **世界档位** | 空闲 / 主机档 / 端侧档 | 角标一个词 | GPU 与 token 归谁、**以哪一档质量产资产**（`tier:host` / `tier:edge`） |

| 显示态 | 主机可达 | 世界档位 | 合法性 | 场景 |
|---|---|---|---|---|
| 总观 | 可达 | **主机档** | ✅ **默认路径** | PC 在线且空闲，后台产场景/背景/剧情 |
| 总观 | 可达 | 空闲 | ✅ | 与门不通（人在用电脑）、冷却期、用户手动停 |
| 总观 | 不可达 | **端侧档** | ✅ | 关电脑、出差、主机不在同一网络：她照样过日子，**还照样产轻资产**（§10.7.3） |
| 总观 | 不可达 | 空闲 | ✅ | 端侧手动停（省电模式） |
| 总观 | 不可达 | 主机档 | ❌ | 逻辑不可能 |
| 显现 | 可达 | 空闲 | ✅ | 消费态：把她叫到面前说话 |
| 显现 | 可达 | 主机档 / 端侧档 | ❌ | 主机档抢 GPU、端侧档抢内存；**进显现必须中止/暂停世界** |
| 显现 | **不可达** | 任一 | ❌ **不可进入** | 没有 LLM 与 TTS，显现不成立 |

四个必须说清的点：

1. **总观是家，不是过渡态。** 设备 90% 时间停在这里。它不依赖 GPU、TTS、LLM，也**不依赖主机是否开着**——这条比任何功能都硬（A14）。
2. **允许为世界做前端视图吗？不允许。** 世界运行期屏幕仍是总观，只多一个词（「世界·主机」/「世界·本地」）。少一套视图 = 少一整条状态分支 + 少一份渲染预算，在 2GB 上是真金白银。
3. **主机档优先，端侧档兜底。** 主机可达就绝不并行走端侧档；端侧档只在主机不可达时接管。**两档共用同一份 `AssetForge`**，差别只在种子来源与质量档位——所以"兜底"不等于"降级成残废"（§10.7.3）。
4. **显现是消费态，离线不降级。** 主机不可达时点角色，只出一句气泡，不加载 Live2D、不出对话框——不给"看得到她但她是哑巴"的错误预期。

### 10.2 资源档位

| 资源 | 总观·空闲 | 总观·**主机档** | 总观·**端侧档** | 显现 |
|---|---|---|---|---|
| 设备渲染内存 | ~120–180 MB | 同左（**不增加**） | 同左 **+≤100 MB**（life.worker + forge.worker + IndexedDB + 地图 + 合成中间层） | ~380–520 MB（Live2D + 背景） |
| PC 显存 | GSV 常驻 4–5 GB | **释放 ≥4 GB** 给生产 | 主机不可达，无占用 | GSV 4–5 GB |
| TTS 进程 | 待机/按需 | **停止**（让显存） | 不可用（无主机） | 必须 warm |
| LLM 调用 | 被动注入 | 每周期一次批处理（§10.9） | **零调用**（状态机出种子 + 文法生成）；云端轻写默认关（可选，日 ≤2k） | 每轮对话 |
| 资产生成 | 无 | GPU 出图 + 模型出种子 | **`forge.worker` CPU 生成**：地图 / 背景合成 / 剧情文法（§10.7.3） | 消费态 |
| 网络 | 局域网 | 局域网 + 可选图源 | **不要求**；有网则用于校时 / 资源更新 / 可选云端轻写 | 局域网 + 可选图源 |
| 目标占用 | 单核 ≤15%，静止 8fps | 同空闲 | 单核 ≤12%（forge 峰值 ≤45%，仅息屏/低帧率时段），息屏后 1 tick/min | 单核 ≤55%，30fps |
| 磁盘写入 | ~0 | 产出落盘（PC 盘） | **≤50 MB/日**，批量提交（eMMC 寿命，R25）；产物配额 ≤500 MB | ~0 |

**切换时必须真正释放**（否则 A12 必挂）：

- **进世界·主机档**：停 TTS → 轮询 `nvidia-smi` 直到显存余量 ≥4GB 才开工（不等就一直不开始，不硬上）
- **出世界·主机档**：中止生产并 checkpoint → 拉起 TTS（预热 ≤8s）→ 显存交回
- **进世界·端侧档**：只保留一个地图图层 + 两个 Worker（`life` + `forge`）；Live2D 必须已卸载
- **总观 → 显现**：**先中止主机档 / 暂停端侧档**，再卸载 tilemap、加载 Live2D。**`forge` 正在跑的任务要么在 200ms 内切片让位，要么整体挂起**（不能一边合成背景一边加载 Live2D）
- **显现 → 总观**：停 `requestAnimationFrame`、卸载 Live2D 纹理与 Cubism 资源、释放音频缓冲、重建 tilemap（≤400ms）、恢复世界
- **任何时刻**：不保留第二套渲染上下文（2GB 上双场景共存是硬风险，见 §10.14）

> 表中数字为设计预算，**M11-T8 / M11-T14 / M11-T16 必须真机实测校准**；若超出，优先砍渲染分辨率与背景图规格，不砍功能。

### 10.3 状态机与迁移

```
【显示态】  屏幕上只有这两档
      ┌──────── 总观（默认 · 唯一常显）────────┐
      │  ▲                                     │
 开关 │  │ 90s 无互动 / 开关拨回 / 掉线 >10s    │ 点击角色 / 开关 / 语音
      ▼  │                                     ▼
      └────────────── 显现（需主机可达）────────┘

【世界档位】
   空闲 ──主机可达 + 五项与门──► 主机档（产资产，抢 GPU）
   空闲 ──主机不可达 ──────────► 端侧档（续经历 + 产轻资产，程序化零 token）
   两档均 → 空闲（用户回来 / 切显现 / 与门破坏 / 单周期跑完 / 手动）

【主机可达】可达 ⇄ 不可达   （心跳 5s；丢失 >60s 判不可达）
```

| 迁移 | 触发 | 守卫条件 | 前置动作 |
|---|---|---|---|
| 总观 → 显现 | 点击角色、开关拨到 ON、语音"显现" | **主机可达**；TTS 预检 ≤300ms；Live2D 可在 1.5s 内加载 | **中止主机档 / 暂停端侧档**；释放 tilemap；提交背景图 |
| 总观 → 显现（**主机不可达**） | 同上 | 主机不可达 | **拒绝**：气泡「主机不在，我听不见」（≤3s 消失），显示态不变（M11-T15） |
| 显现 → 总观 | 开关拨回、90s 无互动、**主机丢失 >10s（强制）** | — | 卸载 Live2D、恢复世界 |
| 空闲 → 主机档 | 五项与门通过 + 显示态=总观 + 距上次中止 ≥30min | 显存余量 ≥4GB；无人值守生产开关开启 | 停 TTS、等显存回落 |
| 空闲 → 端侧档 | **主机心跳丢失 >60s**（WS 断开 + 局域网探测失败，双证） | 显示态=总观 或已息屏；本地资源包完整 | 挂载 LocalRuntime、加载缓存地图、启动 `forge.worker` 队列 |
| 主机档 → 空闲 | 用户任何输入 / 切显现 / 桌面接管 / 单周期跑完 / 与门破坏 | — | 中止任务 + checkpoint |
| 端侧档 → 空闲 | 用户触摸（且主机已恢复）/ 切显现 / 主机恢复后同步完成 / 手动省电 | — | 事件回流、`forge` 任务挂起（不丢队列）、卸载 Worker |
| 主机档 → 端侧档 | 主机突然关机/断网（心跳 + WS 同时失效） | 本地资源包完整 | 中止主机任务、转本地续跑，丢失窗口 ≤60s |
| 端侧档 → 主机档 | 主机恢复且五项与门通过 | 事件已合并 + 端侧资产已入库 | 切数据源，显示态不变；`forge` 队列清空，改由主机档生产 |

**工程约束：**

- **滞回**：显示态切换后 20 秒内不再自动回退；世界最短驻留 10 分钟，主机档单周期上限 30 分钟。
- **抢占优先**：桌面接管 > 显现 > 世界。接管时强制回总观（挂件）；**主机档必须中止**（远程桌面要 GPU），**端侧档可继续跑**（零 GPU，不抢资源）。
- **进显现必停世界**：主机档**中止**（写 checkpoint）、端侧档**暂停**（停 tick、保留状态与事件缓冲）。两档都不能与 Live2D 共存。
- **端侧档是兜底不是替补**：主机可达时永远优先主机档；端侧档只在主机不可用时接管。
- **断连不打断"生活"**：主机丢失只切换档位，不改变显示态。
- **状态分别持久化**：`display_state` / `conn_state` / `work_tier` 各自落盘。重启后一律 = 总观 + 空闲（世界不自动恢复，需重新通过与门或心跳判定），已产出的 checkpoint 与端侧事件缓冲保留不丢。

### 10.4 总观（常显层）

**显示内容**

- 像素地图（房间/屋子/一小片室外），上帝视角
- 角色位置 + 朝向 + 状态气泡（世界档位或 §9 被动块的最新一条）
- 工作 Agent 状态卡：平台名 / 任务摘要 / 状态 / 已耗时；**主机不可达时整卡变灰「主机未连接」**
- 角标：时间、天气（可选）、主机连接点、模型/音色状态
- **世界档位词**（唯一可见痕迹）：主机档「世界·主机」，端侧档「世界·本地」+ 离线点；空闲则无标识
- **场景来源**：她走过的地图可以是她自己生成的（`tier:host` 或 `tier:edge`），换场景不打断移动——总观只问 `AssetStore.getScene()`，不关心谁产的（§10.7.6）

**常显要求（A14 的验收对象，逐条成立）**

| 要求 | 实现 |
|---|---|
| 页面脱离 PC 也能启动 | kiosk 默认指向 `127.0.0.1:8080` 只读壳，**不请求 PC 的 `:12393`** |
| 资源全本地 | 地图/角色/字体/短句池/图标全在资源包内（≤300MB） |
| 数据源可切换 | `LocalRuntime`（Worker + IndexedDB）与 `RemoteRuntime`（WS）双源，视图只订阅 `LifeStore` |
| 不白屏、不转圈、不遮罩 | 冷启动 ≤8s 出画面；主机不可达只是角标变化，**不弹"连接中"界面** |
| 仍可交互 | 点角色出气泡、长按出菜单、地图可拖 |
| 仍有新内容 | 主机不可达时 `forge.worker` 继续产场景/剧情/背景（`tier:edge`），总观地图会真的换新（A16） |

**交互**

| 操作 | 主机可达 | 主机不可达 |
|---|---|---|
| 点击角色 | 进入显现 | 出一句气泡（不加载 Live2D） |
| 滑动开关拨到 ON | 进入显现（§10.15） | 开关回弹 + 提示气泡 |
| 点击 Agent 卡 | 展开任务详情（只读） | — |
| 长按空白 | 菜单：开始/暂停世界生产、静音、亮度、强制重连 | 菜单：亮度、强制重连 |
| 双击角标 | 连接详情（IP、心跳、上次同步） | 同左（显示最后成功时间） |

**实现与性能**

- **渲染**：构建期烘焙的地形/家具/光罩分层 PNG → 运行时 Canvas 2D `drawImage` 合成 + 角色 sprite；**总观态不初始化 WebGL**（选型依据见 §2.6.3，备选 `@pixi/tilemap`）
- **位置与移动**（§2.6.4，必须按此实现，不能用快照）：
  - 下行 `moveTo { targetGrid, path[], speed, t0 }`，事件式，仅在她改变意图时发
  - 前端 `PathAgent` 按 `t0` + `speed` 本地推进格子插值；`state:overview` 带 `pos_checksum` 纠偏，偏差 >1 格才吸附
  - 断连时 `LocalRuntime` 接手**同一个 `PathAgent`**，只换意图来源 → 切换数据源不重置位置
- **状态推送**：在线时 `state:overview` 5s 一次（含 `work_tier`、`conn_state`、`pos_checksum`），<1KB/次；**它不承载位置轨迹**
- **帧率**：静止 8fps、行走 30fps；0.35s/格插值
- 断连时由 LocalRuntime 本地推进保活，**不黑屏**
- **这是唯一在 2GB 上零风险的一屏**，也是所有降级路径的落点

### 10.5 显现（主机依赖态）

> 定位：**"把她叫到面前说话"**。这是全项目唯一需要主机的形态，所以第一道闸门不是 TTS，而是**主机可达**。

**进入前置（硬，按序判定，任一失败即拒绝）**

| # | 前置 | 判定 | 失败表现 |
|---|---|---|---|
| 1 | **主机可达** | 心跳 ≤10s | 气泡「主机不在，我听不见」，**不进入**（A15） |
| 2 | TTS 就绪 | `/tts` 探活或 GSV 端口握手 ≤300ms；失败自动拉起 | 8s 未就绪 → 文字对话框 + 显式提示（不静默失败） |
| 3 | Live2D 资源 | 热态 ≤300ms；冷态先显背景 + 骨架占位，1.5s 补齐 | 静态立绘 + 字幕继续（A10） |
| 4 | 世界已停 | 主机档→中止；端侧档→暂停 | 自动执行 |

**背景图供给链**（按优先级，逐级降级）

| 优先级 | 来源 | 延迟 | 说明 |
|---|---|---|---|
| 1 | **世界主机档预生成的本地图库** | 0 | 首选，进显现前就已存在磁盘 |
| 2 | 当前场景截图 + 像素化/滤镜 | <200ms | 保证与地图一致 |
| 3 | 网络检索照片 | 1–3s | **仅允许 CC0 / 自有 / 已授权源**，默认关闭（§10.14 / R13） |
| 4 | 纯色/渐变 + 装饰 | 0 | 兜底，永不失败 |

规格：1080p、WebP ≤400KB、预解码后上屏、切图淡入 300ms。

**退出路径**

- 正常：90s 无互动 / 开关拨回 → 回总观，恢复世界
- **异常：主机丢失 >10s → 强制回总观**，气泡「主机断开了，我先回去」
- 退出即卸载 Live2D 纹理与音频缓冲，不留后台渲染

### 10.6 世界·主机档（核心生产，需求不变）

> **没有独立前端视图。** 世界在跑时屏幕仍是 §10.4 的总观，只多一个「世界·主机」角标。
> 主机档是 **PC 端后台的一次生产作业**：产出写盘、等待下次显现消费。
> 它是世界的**首选路径**——只要主机可达且与门通过，就用核心机干活；端侧档只在主机不可达时接管（§10.7）。

**进入判定（五项与门，缺一不可）**

| # | 条件 | 判定方式 | 默认阈值 |
|---|---|---|---|
| a | 用户输入空闲 | `GetLastInputInfo`（Win）/ xprintidle（Linux） | ≥ 10 分钟 |
| b | 主机负载低 | CPU 均值 <30%、显存余量 >4GB、磁盘队列 <2 | 连续采样 60s 满足 |
| c | 无用户 agent 任务在跑 | AgentBridge 状态（§10.8，未接入时按配置放行并留痕） | 全部 idle |
| d | 主机端软件主动标记 | GUI「我在用电脑」开关 | 优先级最高，可强制禁止 |
| e | **显示态 = 总观** | ModeController | 显现中一律不进入 |

任一不满足 → 不进入；进入后任一被破坏 → **立即中止**（中止即回空闲，显示态不动，除非是"切显现"导致的）。

**生产任务（按优先级，全部可中断）**

> **生成走 `AssetForge`，两档共用**（§10.7.3）：下表里"本地确定性生成"的部分（地图、背景合成）与端侧档是**同一份代码**；主机档比端侧档多的是**种子来自模型**与**出图走 GPU**。做 `T5` 时就必须按这个边界切分，否则端侧只能重写一遍（`T17`）。

| 优先级 | 产物 | 做法 | 默认 |
|---|---|---|---|
| P0 | 场景地图 | 模型出种子 → 本地确定性生成 | 开 |
| P1 | 生活剧情 | 复用 WakeTrace `content`，本地模板扩写 | 开 |
| P2 | 显现背景图 | 模型出画面 prompt → 本地出图 | 开 |
| P3 | 短视频/动图 | ComfyUI 视频 | **关（低优先）** |

**可中断设计（关键）**

- 每个任务拆成 `plan → produce → commit` 三步，`commit` 是原子写
- 中断时把已完成部分写 `world/outbox/<cycle>/manifest.json`，下次从 checkpoint 续，不重跑
- 产出保留上一版（`v1/v2` 目录），生成失败不影响显现（永远有旧图可用）

**安全边界（agent 自主操作主机）**

- 写盘白名单：仅 `scenes/`、`backgrounds/`、`plots/`；不得写系统目录、不得改配置
- 不执行任意 shell、不联网发布、不安装依赖
- 每次生产留存 manifest（用了什么 prompt、什么种子、产出路径），可回滚可审计

### 10.7 世界·端侧档（主机不可达时的轻型运作）

> **"轻型"指用设备现成硬件干活**：不新增依赖、不占 GPU、不花 token，用两个 Web Worker 把生活接着推进、并继续产出轻资产。
> 触发条件是**主机不可达**（关机 / 断网 / 不在同一网络），**不是设备断网**——设备可以联网，端侧档不要求网络，有网时可用于校时、资源更新与可选增强。
> 端侧档不是主机档的缩小版，而是**同一套生成器换一个种子来源**：主机档用模型想、端侧档用状态机想，**产出的东西是一个家族**（§10.7.3）。

#### 10.7.1 两档定位

| | 世界·主机档（§10.6） | 世界·端侧档（本节） |
|---|---|---|
| 何时启用 | 主机可达 且 五项与门通过 | **主机不可达（心跳丢失 >60s）时接管** |
| 能力来源 | LLM 出种子/prompt、GPU 出图、agent 操作 | 状态机出种子、本地 `AssetForge` 生成 |
| 产物 | 场景、背景图、剧情文本（`tier:host`） | 生活事件流 + **轻资产**：场景、剧情、背景（`tier:edge`） |
| 质量 | 语义丰富、有故事感、出图有细节 | 结构合法、风格一致，**语义与细节低一档**（§10.7.2） |
| 消耗 | GPU 4–5GB + 云端 token | **程序化路径 0 token、0 GPU**；CPU ≤12%（forge 峰值 ≤45%，仅空闲时段） |
| 依赖 | 主机 + 局域网 | **无主机依赖**；网络可选（校时 / 资源更新 / 可选增强） |

#### 10.7.2 能力边界

| 端侧能做（与主机档同质） | 端侧能做（但降档） | 端侧不能做 |
|---|---|---|
| 按本地时间推进作息（起床/吃饭/发呆/睡下） | **生成场景地图**（状态机种子 → `MapForge`） | 任何 LLM 对话 |
| 像素地图上自主漫游、停留、朝向变化 | **写小剧情**（文法生成 30–80 字，无台词） | TTS 发声（要 GSV） |
| 天气与光线（本地种子，日/夜/雨） | **合成背景图**（Canvas 分层，非 AI 出图） | 扩散模型出图 / ComfyUI |
| 模板化生活短句（≤200 条预置 + 变量填充） | 联网时用受限 key 云端轻写剧情（默认关） | 操作主机 agent |
| 记录事件流（IndexedDB，带 uuid 与单调时钟） | 联网时取 CC0 图源（白名单，登记 license） | **写记忆库**（只碰 `life.db`，不碰 L0–L3） |
| 低功耗待机与息屏续跑、唤醒摘要 | — | 产 `tier:host` 资产（达不到那个质量） |

#### 10.7.3 端侧产出：共用 AssetForge，只换种子来源

**凭什么能产——这条决定了整个方案的成本**

主机档的 P0/P1/P2 生产**本来就是"模型出种子/prompt → 本地确定性生成"**（§10.6 任务表、§10.9 的 token 降耗设计）。也就是说：**生成器（模板拼接、Wang tiles、调色板、文法规则）一直在本地，模型只是"想法的来源"。**
端侧要做的事只有一件：**把想法来源从模型换成状态机**。不是造第二套生成器，不是把模型搬上设备。

→ 抽出 **`AssetForge`**（平台无关 TS，跑在 `forge.worker` 或主机 sidecar），两档共用同一份代码、同一 tileset、同一调色板、同一输出 schema。**风格不分裂，只有精细度与语义丰富度不同。**

**三档产物**

| 产物 | 端侧怎么做 | 与主机档的差距 | 日上限 |
|---|---|---|---|
| **场景地图** | 状态机出**种子**（当前时段 / 天气 / 刚发生的事件 / 所在区域）→ `MapForge`：模板拼接 + Wang tiles + 连通性校验 → 场景 JSON（32×24 格） | 主机档的种子带语义（"雨天的旧书店"），端侧种子是**参数组合**；结果仍是合法可走的地图，只是故事感弱 | 6 张 |
| **小剧情** | **文法生成**：`<时间锚点> + <情绪/状态> + <动作序列> + <因果收尾>`，30–80 字；模板 × 变量 × 规则，24h 去重 | 主机档是 LLM 写的 80–200 字，有人称、有对话、有意外；端侧只有"事件 + 感受"，**没有台词** | 8 篇 |
| **背景图** | **Canvas 分层合成** 960×540 → WebP：天空渐变 + 远景剪影 + 地面 + 天气层 + 时间色调，元素取自本地 tileset / 预置图层 | 主机档是 SD/ComfyUI 出图，有细节与光影；端侧是**风格化图层叠加**，同调色板下看着是一家，但经不起细看 | 4 张 |

**明确不做的**（不因本节放开）：LLM 对话、TTS、扩散模型出图、操作主机 agent、写记忆库 L0–L3、产 `tier:host` 资产。

**质量闸门（生成后自检，不过就丢）**

| 产物 | 检查 | 不达标的处理 |
|---|---|---|
| 场景 | 起点可达 ≥3 个兴趣点、空白率 ≤15%、碰撞体不叠 | 换种子重试 ≤2 次 |
| 背景 | 分辨率 ≥960×540、非单色、调色板与基线 ΔE 在区间内 | 重合成 ≤2 次 |
| 剧情 | 非空、含时间锚点、30–80 字、24h 内不重复 | 重生成 ≤1 次 |

三次都不过 → **不写盘**，记 `forge_fail` 计数。宁可没有新东西，也不要把丑东西塞进库里（R23）。

**调度（不许抢生活 tick）**

- 两个 Worker 分离：`life.worker`（tick，P0）与 `forge.worker`（生成，随时让位）
- `forge` 只在 **① 息屏 ② 无互动 60s 后的 1fps 时段 ③ life tick 空闲** 时跑
- 单个生成任务**切片 ≤5s**，片间检查让位标志；收到"进显现 / 出端侧档 / 用户触摸"立即挂起，**队列保留不丢**
- 总观帧率**不允许**因 forge 下降；life tick P95 ≤8ms（A16）

**配额与落盘（eMMC 是消耗品）**

- 端侧产物配额 **≤500 MB**（图 80–120KB/张、场景 JSON ~15KB、剧情 ~1KB），超限按 LRU 淘汰 `tier:edge` 中最久未消费的
- **先写 IndexedDB，批量落盘**（≥8MB 或 ≥30min 一次），日写入 **≤50 MB**（R25）
- 每条产物带 `{tier, origin, seed, created_at, consumed_at, size}`；`origin` ∈ `forge-procedural / forge-grammar / cc0:<源名>`，可审计

**可选：联网增强（默认关）**

设备有网时可以做得更好一点，但**默认不开**，需用户在 GUI 显式授权：

| 增强项 | 做法 | 约束 |
|---|---|---|
| 云端轻写剧情 | 受限 key 调云端 LLM，200–400 字 | 默认关；日 ≤2k output；失败不重试；无 key 静默退回文法（R24） |
| CC0 图源取图 | 预置白名单索引（Kenney / OpenGameArt CC0 / Wikimedia PD），按剧情关键词挑图 | 只允许白名单；登记 license 与 URL 进 manifest；进同一配额（R13 端侧延伸） |

**"0 token"是承诺，不是估计**：程序化路径完全不发网络请求，可用抓包验证（A16 附带检查）。

#### 10.7.4 三条实现前提（缺一条端侧档就不成立）

**① 页面必须能脱离 PC 启动。** 现在前端 44MB 全部由 PC 的 `:12393` 提供，PC 一关就是白屏——这是**总观常显与端侧档共同的最大阻塞**。做法：设备本地起一个**只读静态壳**（`127.0.0.1:8080`，指向设备内资源包），kiosk 默认指向它；**PC 只是数据源，不是宿主**。

- 附带好处：`http://127.0.0.1` 本身属 secure context，`getUserMedia` 可用 → **设备端不必再往信任库装根证书**。§8.13 验证的 HTTPS/WSS 仍可保留（局域网传输加密），但**不再是麦克风的前提**。
- 代价：局域网内走明文 `ws://`。家用局域网可接受，需在 GUI 中说明；若要求加密，再启用网关。
- 资源包 = `frontend/` 44MB + Live2D 模型 + 地图 tileset + 短句池 + 背景图层，eMMC 预算 **≤300MB**（产物另计，≤500MB）。

**② 两套运行时，一个视图。** 视图只订阅抽象 `LifeStore`：`RemoteRuntime`（WS → orchestrator/OLVT）与 `LocalRuntime`（Worker + IndexedDB）。切换数据源**不重建 UI**——与"世界没有独立视图"是同一条原则的延伸。**资产同理**：视图只问 `AssetStore.getBackground()`，不关心它来自 ComfyUI 还是 Canvas。

**③ 端侧必须能自我约束。** tick 预算（单 tick ≤8ms）、内存 **≤100MB** 增量（含 forge 峰值）、产物 ≤500MB、日写入 ≤50MB、Worker 崩溃后 ≤2s 重建且不丢缓冲、24h 不中断。做不到就是不可用的端侧档（A11/A16）。

#### 10.7.5 低功耗（长时间在线的硬约束）

| 状态 | 策略 |
|---|---|
| 有人互动 | 正常帧率（8–30fps） |
| 无互动 60s | 降到 1fps；引擎改用 `setInterval` tick（**不依赖 rAF**，否则息屏即停） |
| 无互动 10min | **息屏**（DPMS / `display_power 0`），life 续跑到 1 tick/min，**forge 进入满速档**（这是产资产的主时段） |
| 唤醒（触摸 / 滑动开关 / 按键） | 亮屏 + 生成"你不在的这段时间"摘要条（含「她新画了 2 张图、写了 3 段」） |
| 端侧内存预算 | **≤100MB 增量**（两 Worker + IndexedDB 索引 + 地图解码 + 合成中间层），M11-T14 实测 |
| 看门狗 | 温度或内存越界 → 先停 forge、再降 tick、再卸图层，不重启进程 |

> 息屏是端侧产资产的最佳窗口：屏幕不刷新、life tick 降到 1/min，CPU 基本空闲，**这正是"夜里她自己在画点什么"的实现方式**。

#### 10.7.6 事件与资产回流（关键）

- 端侧只**追加**事件：`{uuid, src:'device', t_local, t_corrected, kind, payload}`，IndexedDB 环形缓冲上限 2000 条
- **设备时钟会漂**：重连时用主机时间算 `clock_offset`，回填 `t_corrected`，**绝不信任设备绝对时间**
- 事件合并：按 `uuid` 去重 → 按 `t_corrected` 排序 → 只并入 `life.db`；**不改写已存在的 L0–L3 记忆**
- **资产回流**（v0.17 新增）：`tier:edge` 产物并入 `scenes/edge/`、`plots/edge/`、`backgrounds/edge/`，**不覆盖、不删除** `tier:host` 产物；同名冲突以 host 为准、edge 加序号
- **消费优先级**：显现背景 `host > edge > 地图截图 > 纯色`；总观场景 `host > edge > 内置模板`。GUI 提供"只看主机资产"开关
- **主机档如何使用端侧产物**：把"她离线时自己产了什么"作为**上下文素材**（续写方向、背景候选、剧情线索），**不当作记忆事实**——避免端侧的低质量内容污染 L0–L3
- 合并后走 §9 被动注入：她回主机后"记得"这段时间发生过什么，**并且记得自己做过什么**——这是长时在线最值钱的部分

#### 10.7.7 切换

主机恢复 → 先同步事件与资产（≤3s）→ 再切主机档；`forge` 队列里未完成的任务**丢弃不补**（主机档会重新产，没必要让端侧跑完）。**不打断当前动作、不重跑已产出资产**。切档期间显示态不变（仍是总观），角标从「世界·本地」换成「世界·主机」。

### 10.8 Agent 桥接（AgentBridge）—— 接口先定，实现后补

> **决策不变：本期只交接口、配置位与空实现，不接真实平台。**
> 主机上跑哪个 agent 平台尚未确定，现在选定适配器等于把架构钉死在一个未验证的假设上。

总观要显示"主机端正在工作的 agent"，主机档要能提交任务。统一抽象，两个方法一个适配器注册表：

```
AgentBridge (interface)
├─ list_sessions() -> [{platform, task, state, progress, elapsed, pid}]
├─ submit(task) -> job_id          # 仅主机档可用，受空闲判定与白名单约束
└─ kind: str                       # 'stub' | 'logwatch' | 'cli' | 'http'

StubAdapter   ← 本期交付
├─ list_sessions() -> []           # 恒空，总观卡片显示"未接入"
└─ submit()        -> raise NotConfigured
```

| 适配器 | 方式 | 适用 | 状态 |
|---|---|---|---|
| **S Stub** | 恒返回空、submit 不可用 | 先把链路与 UI 跑通 | **本期实现** |
| A1 日志/状态文件监听 | 读 agent 输出目录或状态文件 | 最快落地，只读 | 待平台确定 |
| A2 CLI 包装 | 包一层启动命令，捕获 stdout | 需要提交任务时 | 待平台确定 |
| A3 HTTP / MCP | 平台提供接口 | 最理想，视平台支持 | 待平台确定 |

**接口契约（现在就要稳定的部分）**

- 返回字段固定 `platform / task / state / progress / elapsed / pid`，`state ∈ {running, waiting, failed, idle}`；前端卡片按此渲染，**换适配器不改前端**
- 未接入（`kind='stub'`）时：总观卡片显示「未接入」，主机档 c 条件记"未知"，默认放行并留痕
- **总观只读**（`list_sessions`），**主机档才写**（`submit`），submit 前必须再过一次白名单校验
- 适配器以插件目录加载（`adapters/<name>.py`），配置只填 `agent_bridge.kind`
- **主机不可达时整卡降级为「主机未连接」**，不做重试动画

### 10.9 Token 降耗设计（核心诉求，主机档专属）

**原则：模型只出"参数"，不出"资产"。端侧档消耗恒为 0。**

| 产物 | 朴素做法 | 本方案 | 节省 |
|---|---|---|---|
| 场景地图 | 让模型输出完整 tile 数组（数千格、数万 token） | 只出**种子 JSON**（生物群系/尺寸/6–10 个特征，≈120 output tokens），本地按种子确定性生成 | **≈99%** |
| 生活剧情 | 每次让模型写 800 字 | 优先复用 WakeTrace 的 `content`（唤醒时已付费），本地模板扩写；无新素材才调 1 次 | 70–100% |
| 背景图 | 让模型描述整幅画面 | 只出 60–120 token 画面 prompt，出图交本地 ComfyUI（0 token） | ≈95% |
| 调用次数 | 3 个产物 = 3 次调用 | 1 次 **JSON schema 约束**调用出 3 份 | 调用数 1/3 |

单周期（P0+P1+P2）≈ **400–600 output tokens**，flash 价 ≈ ¥0.005；按日 ≤6 周期 → **≈¥0.03/天，月 <¥1**。

**硬约束**（缺一条就会失控）：

- 必须 `reasoning_effort=none`，否则思考 token 直接吃穿预算（§8.11）
- `max_tokens` 卡死 800，`response_format` 用 JSON schema
- 不开 `tools`（也顺带避开官方 `tools`+`reasoning_content` 的 400，§8.11）
- 失败**不重试**，记 `failed_at`，30 分钟后换下一条
- 日预算护栏：世界 8k output tokens 封顶，超限记 `budget_exhausted` 并停生产至次日

### 10.10 命名与抢占优先级

现有 §4 M9 的"工作模式"指 **RustDesk 桌面接管**；本章的"世界"是**后端生产作业**。两者都叫"模式/工作"，会直接导致实现与沟通出错。

**修正**：M9 更名 **「桌面接管」**（RustDesk 介入时数字人退为悬浮挂件），并明确抢占优先级：

```
桌面接管（最高，强制，跨维度）
   > 显示态：显现  >  世界档位：主机档  >  显示态：总观（默认）
```

- 任何时刻被桌面接管：强制回总观 + 悬浮挂件，**主机档必须中止**（远程桌面本身就要 GPU）；**端侧档可继续**（零 GPU，不抢资源）
- 显现优先于世界：进显现即中止主机档 / 暂停端侧档（§10.3）
- 世界从不改变显示态：它只在总观之下运行（§10.1 矩阵）

### 10.11 失败与降级

| 维度 | 故障 | 表现 | 处理 |
|---|---|---|---|
| 总观 | 本地壳启动失败 | 白屏 | systemd 守护重启（≤5s）；连续 3 次失败进最小兜底页（时间 + 静态角色） |
| 总观 | 资源包缺项 | 缺图/缺模型 | 启动校验清单，缺项用底图 + 提示"资源待同步"，其余功能照常 |
| 总观 | 主机断连 | 地图冻结 | 显示最后一张地图 + 「离线」角标，本地插值动画，不黑屏 |
| 总观 | 主机档角标断更（编排器挂） | 角标停在"工作中" | 30s 无心跳即隐藏角标，避免虚假状态 |
| 总观 | 端侧误判（主机其实可达） | 降级到端侧，能力缩水 | 60s 内重连即切回主机档；判定用 WS + 局域网探测双证 |
| 总观 | IndexedDB 写满（2000 条） | 事件被丢弃 | 环形覆盖最旧条目并计数，恢复时上报 `dropped` |
| 总观 | 设备时钟漂移 | 作息错乱 | 单调时钟 + 亮度/温度兜底；回连即校时 |
| 总观 | **端侧 `forge` 连续失败** | 一段时间没有新场景/新剧情 | 记 `forge_fail`，连续 5 次失败则本轮停生成（冷却 2h）；画面照常，只当"这几天没做什么" |
| 总观 | **端侧产物配额写满** | 不能再存新图 | LRU 淘汰最久未消费的 `tier:edge` 并计数 `evicted`；**永不淘汰 `tier:host`** |
| 总观 | **端侧产物被判定难看** | 用户看到低质资产 | GUI"只看主机资产"开关随时可切；清单显示 `origin` 与 `tier`，可手动删除 |
| 显现 | **请求时主机不可达** | 用户以为坏了 | 气泡「主机不在，我听不见」+ 角标离线点常亮（A15） |
| 显现 | 连接中途丢失 | 对话中断 | 10s 内退回总观 + 气泡说明；世界恢复 |
| 显现 | TTS 未就绪 | 无声音 | 自动拉起，8s 超时 → 文字对话框 + 明确提示 |
| 显现 | Live2D 加载失败 | 角色缺失 | 静态立绘 + 字幕继续可对话 |
| 显现 | 自动播放被拦 | 音频不响 | 提示一次后静音，等用户手势 |
| 显现 | 世界未及时中止导致显存不足 | TTS 起不来 | 强制 kill 生产进程 → 重试一次 → 仍失败降文字模式 |
| 主机档 | 空闲误判（人其实在用） | agent 抢资源 | 立即中止 + 30 分钟冷却 |
| 主机档 | 生产失败 | 无新资产 | 保留旧资产；显现不受影响 |
| 主机档 | 显存未回落 | 出图 OOM | 等 GSV 完全卸载再开工，超时 5min 放弃本轮 |
| 端侧 | 长时间息屏后系统休眠 | 世界停摆 | 关闭系统 suspend，仅做显示层息屏；引擎 tick 保留 |
| 端侧 | Worker 崩溃 | 世界停摆 | 看门狗 ≤2s 重建，事件缓冲不丢，从 `last_tick` 续 |
| 全局 | 状态丢失 | 重启后异常 | 一律回 总观 + 空闲，保留世界 checkpoint 与端侧事件缓冲 |

### 10.14 实施顺序、依赖与风险

**依赖**：M11 依赖 M5（前端可控）、M6（地图与 schema）、M7（生活流供剧情）。

**顺序**（总观常显 + 端侧先行，主机档紧随）：

```
M6-T2/T3（schema + tilemap） → M11-T12（离线壳/资源包）
   → M11-T2（总观，含不可达形态） → M11-T16（常显实测，A14）
   → M11-T11（端侧引擎） → M11-T1（档位状态机） → M11-T15（不可达拦截）
   → M11-T10（切换交互） → M11-T3（显现）
   → M11-T4/T5（主机档与门 + 生产） → M11-T6 → M11-T7（Stub）
   → M11-T13（事件回流） → M11-T8/T14（资源与长时在线实测）
   → M11-T17（AssetForge 抽取，与 T5 合并） → M11-T18/T19/T20（端侧生成与调度）
   → M11-T21（端侧资产生效） → A16/A16b 实测
   ── 之后 ── M11-T7b（AgentBridge 真适配器）/ M11-T9（ComfyUI）
```

**为什么这个顺序**：`T12`（离线壳）不落，总观在主机不在时就是白屏，`T2/T16` 无从验收，端侧档也不成立；`T15` 与 `T3` 必须成对验收（A15 是"拒绝"的正确性，比"进入"更容易漏测）；主机档（`T4/T5/T6`）排在显现之后，因为它依赖 TTS 让出显存这一条被先验证。
**`T17` 为什么必须与 `T5` 同时做**：端侧的生成能力不是"新写一套"，而是把 `T5` 的生成器抽出来共用（§10.7.3）。如果 `T5` 直接写成主机专用（Python 里调 GPU、路径写死在 PC），端侧就得重写一遍——那才是真正的"两套生成器"和风格分裂的来源。**先在 `T17` 里把生成器做成纯函数（种子 → 产物），两档自然共用。**

**`BLOCK` 说明**：M11-T7 只交接口与空实现，`submit()` 抛 `NotConfigured`；主机档生产的"提交任务"路径先走本地内置生成器（不依赖任何外部 agent 平台），M11 全链可独立跑通。

**待定与风险**

- **AgentBridge 接哪个平台未定**（§10.8）：当前只用 Stub，总观卡片显示「未接入」。接平台是独立后续任务，不阻塞 M11。
- **滑动开关的硬件形态未定**（§10.15）：本期只做软件虚拟开关 + 预留端侧接口。
- **主机可达但与门长期不通时她是否停摆**（如整天在用电脑）：当前按"空闲"处理，不降端侧档（避免两套并行）。可选方案：>6h 后允许端侧档接管生活（默认关）——**待需求方定**。
- **端侧与主机产物的质量落差**（取代"风格分裂"）：风格由共用 `AssetForge` + 同一 tileset/调色板保证，但质量差一档。对策：`tier` 标记 + 显现优先 host + GUI"只看主机资产" + 质量闸门（R20/R23）。**真正需要盯的是"差到难看"**，不是"不一样"。
- **端侧生成是否真的不抢资源**：`forge.worker` 与 `life.worker` 同抢 4×A55，`Canvas` 合成峰值可能触发降帧 → M11-T20 必须做切片让位 + 帧率实测（A16）；若实测扛不住，**降级顺序**为：先砍背景合成（最贵），再砍地图生成，剧情文法最便宜留到最后。
- **端侧出图这件事的期望管理**：Canvas 合成不是"AI 出图"，用户可能期待离线也能出 SD 质感的图。GUI 与文档必须写清"离线背景是图层合成"，并在资产清单里显示 `origin`，不给错误预期（对标 R21 的同类问题）。
- **联网增强的 key 管理**（若开）：设备是移动终端，key 一旦泄露影响不止一台机器 → 受限 key + 日额度 + 远程吊销 + 不进日志（R24）；**默认关**，不给"默认省钱反被刷"的机会。
- **设备时钟漂移**：长期离线可能偏差数小时；合并靠 `clock_offset` 校正，端侧期间的作息时间点本身可能失真 → 用单调时钟 + 亮度/温度兜底，不追求精确。
- **息屏与系统休眠的边界**：只关显示层，不能进 suspend（否则 JS tick 停），需在 Armbian 上关掉 `systemd` 自动休眠并实测功耗（M11-T14）。
- **背景图走网络源**：版权与合规风险，默认关闭；只允许 CC0/自有/授权源，且需在 GUI 中显式开启（R13）。
- **主机档 agent 自主操作**：必须有白名单 + 可回滚 + 无网络发布；首版只做 P0/P1（纯本地内容），不接 ComfyUI。
- **2GB 下 Live2D 与 tilemap 共存**：内存峰值未知，可能必须"单态独占"（切显现时卸载 tilemap 图层）；M11-T8 实测决定。
- **端侧档叠加后 2GB 余量**：空闲 180MB + 端侧 **100MB**（含 forge）已在 2GB 中占去相当比例；若实测超限，降级顺序为 停背景合成 → 停地图生成 → 只写事件不渲染，M11-T14/T20 决定。
- **GSV 与 ComfyUI 显存不能同时驻留**（12GB 卡）：主机档必须确认 GSV 已卸载再开工，否则直接 OOM。
- **世界期间"无界面"的验证盲区**：没有独立视图，容易出现"逻辑在跑但前端毫无感知"的排障困难 → 角标必须实时（`state:overview` 5s 推送），`state_log` 要有档位切换与中止原因记录（R16）。

### 10.15 交互硬件：滑动二切开关（预留）

**需求**：一个物理开关，两档位直接对应**总观 ⇄ 显现**。世界不进开关——它不是显示态。

| 项 | 设计 |
|---|---|
| 形态 | **滑动式两档**（非按键）：拨到 A 档 = 总观，拨到 B 档 = 显现。触点手感明确，一眼看出当前档位 |
| 位置 | 屏幕边框侧面（手持/放置都不误触） |
| 电气 | 单刀双掷（SPDT）拨动开关，一端接 GND，另一端上拉 GPIO；或霍尔 + 磁滑块（无机械寿命问题，待定） |
| 端侧 | GPIO 电平变化 → `gpio-keys` 映射为 input event → 前端监听 `keydown`/`evdev`。去抖 ≥50ms，状态变化即上报 |
| 兜底 | 硬件未就绪时，前端提供**屏幕内虚拟滑动开关**（同样两档，右下角），逻辑完全一致，硬件到位后只换事件源 |
| 主机不可达时拨到 B | **拒绝 + 回弹到 A + 气泡提示**，不机械锁死（主机在时的一键性必须保留） |
| 息屏唤醒 | 端侧息屏时，**拨动开关必须能唤醒屏幕**（GPIO 中断 → 亮屏），这是它相对触屏的唯一硬件优势 |
| 与世界的关系 | 拨到显现 = 中止主机档 / 暂停端侧档 + 加载 Live2D；拨回总观 = 卸载 Live2D + 恢复世界。**不允许用开关直接开世界** |
| 优先级 | 桌面接管 > 开关 > 90s 超时（被接管时开关不生效，避免与远程桌面抢状态） |

**分期**：

- **本期（M11-T10）**：虚拟开关 + 事件抽象（`DisplaySwitchSource` 接口，`virtual` / `gpio` 两种实现），GPIO 实现留空
- **后续（M4 硬件定型后）**：确认板子是否有空余 GPIO（RK3566 屏排线常占用大量 IO，需核对），再实装。若无可用 IO → 永远停在虚拟开关，不影响功能

**风险**：机械拨动开关有寿命与进灰问题（移动设备尤其）；磁吸/霍尔方案更耐久但成本略高。此决策等硬件选型时定。
